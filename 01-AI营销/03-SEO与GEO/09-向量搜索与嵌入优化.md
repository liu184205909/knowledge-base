## 核心认知

> **架构同构**：向量检索是"查询时现算"的 AI 版本——离线把语料向量化、建向量索引（存量），查询时把问题转向量、检索最接近段落、RAG 合成答案（流量）。这与 [02-Google-SEO核心机制](./02-Google-SEO核心机制.md) 的"索引时存 / 查询时算"是同一套底层架构，也是"对 SEO 有害 = 对 AI 搜索也有害"的根因。

搜索引擎的底层逻辑已经从**关键词匹配**转向**语义向量匹配**。

| 旧范式 | 新范式 |
|--------|--------|
| 用户输入关键词 → 匹配包含相同词的页面 | 用户输入意图 → 转化为向量 → 匹配语义最接近的页面 |
| TF-IDF（词频-逆文档频率） | Dense Vector Embeddings（稠密向量嵌入） |
| 排名 = 关键词出现频率 + 权重 | 排名 = 余弦相似度（Cosine Similarity） |
| 工具：SEMrush/Ahrefs 关键词数据 | 工具：向量嵌入分析（Vectour、Screaming Frog + OpenAI） |

**关键数据**：67.82% 的 Google AI Overview 引用来源不在传统搜索前10排名中。AI 不选"排名最好的页面"，它选"向量空间最近的段落"。

## 一、什么是向量嵌入

### 基本概念

向量嵌入（Vector Embedding）是将文本、图片或其他内容转化为**一组数字**（向量）的过程。这组数字在高维空间中代表了内容的语义含义。

经典例子：
```
向量运算: king - man + woman ≈ queen
```
同一语义空间中，含义相近的内容在数学上距离更近。

### 稀疏 vs 稠密嵌入

| 类型 | 代表技术 | 特点 | 局限 |
|------|---------|------|------|
| **稀疏嵌入** | TF-IDF、BM25 | 大部分维度为0，只有命中的词有值；精确匹配 | 无法理解同义词、语义关系 |
| **稠密嵌入** | Word2Vec、BERT、Gemini Embedding | 所有维度都有值，捕获语义关系 | 需要训练数据和计算资源 |

搜索引擎（Google）现在使用**混合检索**（Hybrid Search）：稀疏嵌入做基础匹配 + 稠密嵌入做语义理解。

### 余弦相似度

搜索引擎通过余弦相似度（Cosine Similarity）计算两个向量的接近程度：

| 得分 | 含义 |
|------|------|
| 接近 1 | 高度相关 |
| 接近 0 | 无关 |
| 接近 -1 | 相反 |

**实操意义**：你的页面向量与用户查询向量越接近（余弦相似度越高），被检索到的概率越大。

## 二、搜索引擎如何使用向量

### Google 的向量检索演进

| 时间 | 技术 | 突破 |
|------|------|------|
| 2013 | Word2Vec（Mikolov） | 所有英文词转化为向量 |
| 2018 | BERT | 双向上下文理解，考虑前后文关系 |
| 2023+ | Gemini Embedding | 多模态嵌入（文本+图片+视频+音频） |
| 2026 | Gemini Embedding 2 | 统一嵌入空间，100种语言 |

### AI 引用流程中的向量

```
用户查询
  ↓
查询转化为向量（Query Embedding）
  ↓
在向量数据库中检索最接近的文档段落
  ↓ 余弦相似度排序
LLM 合成答案（RAG）
  ↓
引用最相关段落作为来源
```

**关键洞察**（Mike King）：LLM 使用向量嵌入进行查询响应的**所有阶段**——提示词评估、信息检索、生成回答。对齐这个流程是 GEO 的核心。

## 三、为什么向量嵌入对 SEO/GEO 至关重要

### 传统 SEO 工具的盲区

传统 SEO 工具（Ahrefs、SEMrush、Moz）基于**倒排索引**（Inverted Index）工作——本质上是关键词到页面的映射。它们**完全无法分析向量维度**。

这意味着：
- 你的关键词排名好 ≠ 你的向量接近度高
- AI Overview 引用的页面可能关键词覆盖很弱，但语义向量非常接近
- **竞争对手页面可能不在关键词排名中，但在向量空间中比你更接近用户意图**

### Gemini Embedding 2 的多模态影响

Google 的 Gemini Embedding 2 将文本、图片、视频、音频映射到**同一个嵌入空间**。

| 含义 | 说明 |
|------|------|
| 视频和音频现在与文字**直接竞争** | 低质量多媒体资产可能拉低整体相关性 |
| 多模态 ≠ 文字 + 图片各做各的 | 所有格式在同一个语义空间中被评估 |
| 实操建议 | 审查网站多媒体资产的相关性、准确性和时效性 |

## 四、向量分析实操框架

> 综合 Mike King（iPullRank）、Cyrus Shepard、Datos 等实践者方法论

### 4.1 竞品向量分析

**步骤**：

```
1. 向量化你的页面 → 计算与目标查询的余弦相似度
    ↓ 如果得分低，页面与查询语义不匹配
2. 按段落拆解分析 → 找出得分最高和最低的段落
    ↓ 搜索引擎按固定 token 大小 + 布局边界分析
3. 对比竞品 → 向量化竞品页面，找出差距段落
    ↓ 识别竞品得分高但你没有覆盖的语义维度
4. 优化 → 针对性改进低分段落
```

**工具链**：

| 工具 | 用途 |
|------|------|
| Screaming Frog + OpenAI Embeddings | 批量生成页面向量 |
| Vectour（开源） | 分析实体网络和向量关系 |
| Python + OpenAI API | 自定义向量分析脚本 |

### 4.2 内容优化：Chunking + 语义三元组

#### Chunking（分块优化）

搜索引擎按固定 token 大小分析页面，按标题和段落边界切分。

**原则**：每个段落只表达一个核心观点。

```
❌ 错误：一段文字同时讨论 4 个不同话题
   → 语义被稀释，向量指向不明确

✅ 正确：一段文字只聚焦一个具体观点
   → 语义集中，向量指向精准，更容易被检索
```

#### 语义三元组（Semantic Triples）

用**主语-谓语-宾语**的简单句式表达核心声明。

```
❌ "Crystal healing bracelets are crafted with natural stones that have been used throughout history for their purported metaphysical properties."

✅ "Amethyst is a purple quartz crystal used in crystal healing."

效果：LLM 更容易理解 → 更容易被引用 → 人类也更容易阅读
```

### 4.3 权威性聚焦：Stay in Your Lane

搜索引擎通过计算网站的**平均嵌入向量**来判断主题权威性，然后将每个页面与这个平均值比较。

| 场景 | 结果 |
|------|------|
| 页面与网站主题高度一致 | 强化主题权威性 |
| 页面与网站主题偏离（"随机谈论香蕉"） | 削弱整体权威性 |

**实操**：识别并修剪与核心主题偏离的内容（outlier content），或将其重定向到相关页面。iPullRank 报告称这一操作"立即见效"。

### 4.4 技术SEO的向量应用

| 应用场景 | 向量分析方法 |
|----------|------------|
| **内链结构** | 计算所有页面的向量相似度，相似度高的页面互链 |
| **重定向映射** | 向量相似度帮助找到最佳目标页面 |
| **内容聚类** | 向量化页面群组，识别架构差距和机会 |
| **查询意图分析** | 交叉分析 AI Overview 引用 + 排名关键词，找到页面多意图覆盖 |

### 4.5 Frank van Dijk 的向量化 SEO 框架

基于余弦相似度（Cosine Similarity）的页面关系判定框架：

| 相似度范围 | 判定 | 行动 |
|-----------|------|------|
| **< 0.70** | 不相关 | 不管它 |
| **0.70 - 0.95** | 语义相关但不重复 | **做内链（甜点区）** |
| **> 0.95** | 语义高度重合 | 查重/合并（Cannibalization） |

#### Google 排名四层架构（DOJ 反垄断案披露）

Frank van Dijk 将搜索过程拆解为四层：

| 层级 | 技术 | 说明 |
|------|------|------|
| **1. Keyword matching** | BM25 倒排索引 | 门槛——通过才能进入候选池 |
| **2. RankEmbed** | 语义向量匹配 | 竞争力——语义空间中的位置 |
| **3. DeepRank** | 深度神经网络 | 深度评分 |
| **4. NavBoost** | 用户点击信号 | 行为校准 |

**核心判断**：第一层是门槛，第二三层才是竞争力所在。

#### 实操路线图

| 阶段 | 工具 | 说明 |
|------|------|------|
| 零代码 | Screaming Frog v20+（内置 Embedding） | 填入 API Key 即可批量生成向量 |
| 脚本化 | Python 脚本 | 精细控制分析逻辑 |
| 工程化 | BigQuery 构建 Vector DB | 大规模向量存储和检索 |
| 团队化 | 封装为工作流 | 重复执行，团队协作 |

### 4.6 竞品主题聚焦度分析（Topic Scatter Analysis）

> 来源：鸭老师SEO，经向量降维可视化验证。

#### 问题

§4.3 "Stay in Your Lane" 告诉我们主题聚焦能强化权威性，但缺少一个关键能力：**如何量化一个网站的「主题聚焦度」，并跨竞品对比？**

传统方法只能凭直觉判断"这个站内容太散"或"那个站很聚焦"。向量降维可视化提供了数据驱动的答案。

#### 方法

```
1. 采集竞品全站页面内容（sitemap → 爬取正文）
    ↓
2. 生成页面级向量嵌入（OpenAI / Gemini Embedding）
    ↓
3. 聚类分析（K-Means，识别主题簇）
    ↓
4. 降维到 2D（PCA / t-SNE / UMAP）
    ↓
5. 散点图可视化 —— 每个竞品一张图，对比主题分布
    ↓
6. 交叉 ahrefs 流量数据，验证聚焦度与流量效率的关系
```

#### 核心发现

将向量映射到 2D 坐标后，能直观看出竞品之间的主题分布差异：

| 散点图特征 | 含义 | 对策 |
|-----------|------|------|
| **点高度集中** | 主题聚焦，内容围绕核心领域 | 主题权威性强，应继续保持 |
| **点高度分散** | 主题散乱，覆盖面广但不深 | 流量效率低，应收缩聚焦 |
| **出现孤立簇** | 存在与核心主题偏离的内容板块 | 评估是否值得保留，或修剪/重定向 |
| **簇与簇之间有间隙** | 主题覆盖有缺口 | 识别间隙对应的关键词机会，补齐内容 |

**关键数据点**：交叉对比 ahrefs 流量发现，**主题越聚焦的站点，单页面流量效率越高**。散布越大的站点虽然总页面多，但单页产出低，说明"什么都有 = 什么都不精"。

#### 聚焦度指标（示意）

| 指标 | 计算方式 | 判断 |
|------|---------|------|
| **平均簇内距离** | 所有点到所属簇中心的平均欧氏距离 | 越小 = 簇越紧凑 = 内容越聚焦 |
| **簇间离散度** | 各簇中心之间的平均距离 | 越大 = 主题越分散 |
| **离群点比例** | 与任何簇中心距离 > 阈值的点占比 | 越高 = 偏离主题的内容越多 |
| **流量效率比** | ahrefs 月流量 / 索引页面数 | 聚焦度高 → 流量效率高 |

#### 工具链

| 步骤 | 工具 |
|------|------|
| 采集页面 | Sitemap MCP / Screaming Frog / `requests + BeautifulSoup` |
| 生成嵌入 | OpenAI Embedding API / Gemini Embedding API |
| 聚类 + 降维 | `scikit-learn`（KMeans + PCA/TSNE/UMAP） |
| 可视化 | `matplotlib` / `plotly`（散点图 + 簇着色） |
| 流量对比 | ahrefs / SEMrush（导出流量数据交叉分析） |

#### 与 §4.3 "Stay in Your Lane" 的关系

§4.3 给出了原则（保持主题聚焦），本节给出了**测量方法**：

- §4.3 说"识别并修剪偏离内容" → §4.6 告诉你**哪些内容是偏离的**（散点图上的孤立点/远离核心簇的点）
- §4.3 说"页面与网站主题偏离会削弱权威性" → §4.6 给出**可视化证据**（散布大的站点 vs 散布小的站点）

#### 局限性

- 降维到 2D 会丢失高维空间信息，散点图反映的是**趋势和相对关系**，不是精确计算
- 聚焦度与流量效率的因果关系需更多样本验证（当前为方向性判断，非统计结论）
- 与 Google 内部的 RankEmbed / NavBoost 体系不同，但**趋势原理相近**——Google 同样通过向量空间判断主题权威性
- 适用于**内容站/博客站/独立站**的竞品对比，对平台型/UGC 型网站分析意义有限

## 五、从关键词策略到向量策略的转变

### 数据驱动的转变证据

| 发现 | 来源 |
|------|------|
| 排名第1与AI引用第1的重叠度 < 20% | Arc Intermedia / 多项研究 |
| AI Overview 引用的页面 67.82% 不在传统搜索前10 | AirOps |
| 语义相关性得分与SERP排名**强相关**，但TF-IDF相关性弱 | Lumar（2000+查询研究） |
| 短元素（Title/H1）的语义相关性比正文内容更影响排名 | Lumar 研究 |

### 关键词策略 vs 向量策略

| 维度 | 关键词策略 | 向量策略 |
|------|-----------|---------|
| 研究方法 | 关键词工具（SEMrush/Ahrefs） | 向量嵌入 + 余弦相似度分析 |
| 内容规划 | 基于搜索量排序 | 基于语义距离和意图聚类 |
| 竞品分析 | 排名差距分析 | 向量空间差距分析 |
| 内链策略 | 基于主题相关性的手动判断 | 基于向量相似度的数据驱动 |
| 优化目标 | 关键词密度和覆盖 | 语义密度和实体关系清晰度 |

### 向量聚类 ≠ 关键词聚类

> 来源：鸭老师SEO，Screaming Frog Visualisations 向量可视化分析

行业主流的主题规划方法是关键词聚类（按词根、按字面相似度把词分组）。但关键词聚类反映的是**人对主题的理解方式**，而 Google 理解页面主题的方式是 embedding。由此产生两个反直觉现象：

1. **字面同义词在向量空间可能很远**：两个词看起来近义，但上下文分布不同、背后的搜索任务不同，向量会把它们放到相距很远的位置。按字面聚成一类塞进同一个页面，页面的主题信号在 Google 的向量空间里是**分裂的**
2. **标题毫无字面重叠的文章，向量可能很近**：它们在竞争同一个语义位置——这是关键词工具**查不出来**的内容蚕食形态

> 主题规划的依据应当从"这些词长得像不像"转向"这些内容在向量空间里落在哪"。

### 离群点处置路径

向量聚类图中最实用的读法是找离群点——那些远离质心、悬在点云边缘甚至独立成簇的页面，就是偏离站点主题的页面。

| 离群点类型 | 特征 | 处置 |
|-----------|------|------|
| **离群 + 无流量** | 对主题信号纯负贡献 | **最优先修剪**——删除、noindex 或重定向到相关核心页面 |
| **离群 + 有流量** | 偏题但有价值 | 业务判断：保留为例外，或这块内容应独立成站/独立目录 |
| **离群 + 成片聚集** | 一个游离的小簇 = "双质心" | 站点实际上在同时做两个主题，量化两团点云的距离，决定拆分还是聚焦 |

### Clickstream 嵌入：用户行为驱动的向量

Datos 提出的新范式：不再基于文本语义训练嵌入，而是基于**用户实际搜索和点击行为**训练嵌入。

| 维度 | 传统文本嵌入 | Clickstream 嵌入 |
|------|------------|-----------------|
| 训练数据 | 文本语料 | 用户搜索+点击序列 |
| 捕获能力 | 语义关系 | 语义 + 导航模式 + 意图流 |
| 优势 | 不依赖用户数据 | 反映真实用户行为 |
| 应用 | 通用语义搜索 | 发现隐藏竞品、意图聚类、内容优化 |

## 附录：向量嵌入 + Screaming Frog 实战工作流

> **迁入说明**：原 14 号 §11，因 09 号是向量主题权威文档，本章作为附录归入。

> 来源：Mike King / iPullRank — [Vector Embeddings Is All You Need](https://ipullrank.com/vector-embeddings-is-all-you-need)（2025-2026）
> 交叉参考：[09-向量搜索与嵌入优化.md](./09-向量搜索与嵌入优化.md)（理论层）

### 核心理念：从词法匹配到语义检索

Google的检索架构已从纯BM25关键词匹配演进为**混合检索**：

```
用户查询
  ├─ BM25（词法检索）→ 精确/短语匹配
  ├─ SCaNN（向量搜索）→ 语义近邻检索
  ├─ BERT（稠密嵌入）→ 查询理解
  └─ RM3（重排序）→ 结果融合
```

**关键洞察**：即使你的页面没有包含查询关键词，只要语义嵌入足够近，仍然可以排名。这意味着SEO需要从"关键词覆盖"转向"语义覆盖"。

### 5大SEO应用场景（含代码逻辑）

#### 1. 关键词映射（Keyword Mapping）

**目标**：为每个关键词自动匹配最相关的落地页。

```
逻辑：
- 为所有页面URL生成向量嵌入
- 为所有目标关键词生成向量嵌入
- SCaNN最近邻检索：每个关键词 → 最相似的页面
- 输出：keyword → best_page 映射表
```

**SEO价值**：替代人工关键词-页面映射，处理10K+关键词时效率提升100倍。

#### 2. 关键词相关性评分（Relevance Scoring）

**目标**：量化关键词与页面的语义相关性。

```
逻辑：
- 计算关键词嵌入与页面嵌入的余弦相似度
- 转换为0-100分数：score = (similarity + 1) / 2 * 100
- 输出：keyword × page 相关性矩阵
```

**SEO价值**：识别"高搜索量但低相关性"的错配，指导内容重构。

#### 3. 内链与重定向映射（Internal Linking & Redirects）

**目标**：找到语义最相似的页面对，建立内链或301重定向。

```
逻辑：
- 计算所有页面之间的余弦相似度
- 过滤：相似度 > 阈值 且 非同一路径
- 输出：source_page → target_page 候选对
```

**SEO价值**：自动化内链建设，替代人工"相关文章"推荐。

#### 4. 外链建设目标识别（Link Building Targets）

**目标**：在外部网站中找到与你的页面语义相关的潜在链接目标。

```
逻辑：
- 为你的页面和外部候选页面分别生成嵌入
- 余弦相似度 ≥ 0.6 → 高价值链接目标
- 0.3-0.6 → 中等价值
- < 0.3 → 不相关
```

**SEO价值**：从"DA分数"转向"语义相关性"评估外链质量，更符合Google的链接评估逻辑。

#### 5. 内容聚类（Content Clustering）

**目标**：用BERTopic发现内容主题集群，可视化内容覆盖盲区。

```
逻辑：
- 所有页面嵌入 → BERTopic建模
- t-SNE降维 → 2D可视化
- ChatGPT自动生成聚类标签
- 输出：topic clusters + 孤立页面识别
```

**SEO价值**：发现内容孤岛、识别主题覆盖缺口、优化hub-and-spoke结构。

### Screaming Frog Visualisations 实操指南（SF v22+）

> SF v22+ 内置了 Embedding 功能和 Visualisations 模块，不再需要 Custom JS。以下是完整操作方法。

#### Content Cluster Diagram 配置步骤

```
Config > API Access > AI → 连接 AI Provider（推荐 Gemini，便宜且效果好）
Config > Content > Area → 框定正文区域，排除导航/页脚/弹窗（关键！否则共享模板文本会让所有页面被拉紧）
Config > Spider > Extraction → 勾选 Store HTML
Config > Content > Embeddings → 勾选 Enable + Semantic Similarity + Low Relevance
     → 相似度阈值默认 0.95（蚕食检测），低相关性阈值默认 0.4（离群点）
爬取网站 → 等待爬取和 API 进度条都到 100%
Crawl Analysis → Start（可设置自动运行）
Visualisations > Content Cluster Diagram（最多显示 10,000 页面）
```

#### 关键优化技巧

| 技巧 | 说明 |
|------|------|
| **精炼 Content Area** | 排除导航栏、页脚、Cookie 提示等重复文本。否则全站页面因共享模板文本被强行拉紧，聚类结果失真 |
| **降低 Embedding 维度** | 1024 维降到 256 维不损失精度，Crawl Analysis 速度提升 30%，t-SNE 降维速度提升 55%。OpenAI 参数 `dimensions`，Gemini 参数 `outputDimensionality` |
| **处理大页面 Token 限制** | Advanced 标签启用 `Limit Page Content`（默认 5000 字符）。缺少 embedding 的页面可右键 `Request API Data` 批量重请求 |
| **Gemini RPM 注意** | 免费层实际限制约 20 RPM，付费 Tier 1 可到 3000 RPM |
| **画布自动缩放陷阱** | 聚类图会自动缩放铺满视图，看起来松散的点云未必真发散。判断聚合程度要看坐标的实际数值范围，不能凭视觉印象 |

#### 内容蚕食检测

**Semantically Similar 过滤器**（Content Tab）比可视化图更实用：
- 相似度 > 0.95 的页面对 = 高度蚕食嫌疑
- `Bulk Export > Content > Semantically Similar` 导出完整列表
- 结合 GSC/GA4 流量数据，对每组相似页面做决策：

| 决策 | 条件 | 操作 |
|------|------|------|
| **Merge** | 两篇覆盖相同主题，各自分流搜索可见性 | 合并为一篇综合指南，弱 URL 做 301 |
| **Refresh** | 离群但有潜力，缺少正确术语/案例 | 重写对齐主题簇，不是删除 |
| **Prune** | 离群 + 无流量 + 无战略价值 | 删除/noindex，释放爬取预算 |

#### Force-Directed Crawl Diagram 六大应用场景

| 场景 | 操作方法 | 发现 |
|------|---------|------|
| **未收录重要页面** | 绿色=可索引，浅红=不可索引 | 首页被意外 noindex、404 但被多个高流量页面链接的旧页 |
| **深埋的重要页面** | 看外围浅绿色节点（远离首页的深层页面） | 核心服务页被埋在 4 层深度下 |
| **GSC 流量热点** | Settings 选 GSC Clicks 缩放，深绿=高点击 | 20 分钟完成全站点击分布分析 |
| **外链实力分布** | 连接 Ahrefs API，URL Rating 缩放 | 哪些博客开始自然获得外链 |
| **全站速度审查** | 连接 PSI API | 迁移前发现首页和关键页面速度差 |
| **内链分布审查** | Unique Inlinks 或 LinkScore 缩放，浅绿=内链少 | 商业价值博文只有 3 个内链 |

#### 基于语义的内链优化流程

```
1. Content Cluster Diagram 中右键节点 → Show Inlinks Within Cluster
   → 检查语义相似的页面是否互相链接
2. 两个语义相似但在不同 Segment 的页面 = 明确的内链机会
3. Bulk Export > Links > All Inlinks → 导出锚文本
4. 用 Custom Search 找正文中反复出现但未链接的术语
5. 非描述性锚文本（"点击这里"/"阅读更多"）→ 替换为 2-5 词的描述性锚文本
6. 内链建设优先级：强簇锚点页 → 向弱/新页面注入链接
```

#### 可视化选择指南

| 目标 | 推荐可视化 |
|------|-----------|
| 看主题分布 + 离群点 | Content Cluster Diagram |
| 看爬虫视角的链接架构 | Force-Directed Crawl Diagram |
| 看 URL 目录结构 | Force-Directed Directory Diagram |
| 大型站点（10000+页面） | 3D Force-Directed Diagram |
| 内链分析 | Force-Directed Crawl Diagram + Content Cluster 交叉 |

**交叉验证原则**：当 Content Cluster Diagram 里的离群页面，同时也是 Crawl Diagram 里深度最深、内链最少的边缘节点时，两个独立数据源收敛，修剪决策的置信度远高于单一证据。语义上偏题 + 结构上边缘化 = 几乎不存在误判空间。
