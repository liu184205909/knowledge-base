# 多语言站点建站方案（TranslatePress + DeepSeek 定案版）

> **定位**：英文主站扩展小语种市场的建站与内容架构方案
> **架构一句话**：TranslatePress 管语言关联（含 hreflang 自动输出），DeepSeek 定制引擎在插件层翻译，英文页面走既有 Elementor 流水线
> **版本**：2026-10-09 重写——原 Polylang+DeepL 方案（2026-08-26）已被定案取代（Polylang REST glue code 作废）；现行栈实测于 goearthward.com

---

## 一、架构与定案

- **TranslatePress Multilingual 3.2.3 + Business 1.5.8**：语言标记、页面关联、hreflang（已验证）、语言切换器
- **13 语言目标**：de/es/fr/ja/ko/it/zh-TW/nl/pl/id/ar/pt-BR + en 原生
- **引擎=DeepSeek**（2026-07-04 定案，弃 DeepL——成本更低+可注入规则；DeepSeek key 在 `~/.env`）。注意：智谱 coding plan 额度不能用于翻译（编码订阅≠通用 API 配额）

**定制引擎与规则真源**（`01-AI营销/02-自动化工具库/03-WordPress建站/`）：
1. `TranslatePress-翻译规则与术语表.md`——7 层规则（原文净化/13 语言术语表/禁用词/调性/SEO 意图/HTML 保护/few-shot）+ 质检门
2. `earthward-deepseek-translatepress.php`——定制引擎插件（继承 TRP_Machine_Translator）：system+user 双 message 注入规则、JSON mode 输出、HTML 结构校验失败回退原文、内置术语表与原文净化

**部署纪律**：独立插件 zip 上传或 mu-plugin——**禁用 Code Snippets**（该通道在 plugins_loaded 阶段注册引擎不可靠，实测前端不执行）。引擎注册 4 hook + 2 语言适配 filter 的细节见上述交付物。

## 二、机器翻译不能替代的两个工序（引擎无关，DeepSeek 同样适用）

| 工序 | 为什么引擎做不了 | 怎么做 |
|---|---|---|
| **① 本地关键词研究 → TKD** | 直译产出的是"英文关键词的本地直译"，不是本地人真实搜索词 | DataForSEO 换 `location_code`（德=2276）查本地 SERP+本地词根；**Title/Meta/H1/slug 必须用本地真实搜索词**，正文可机翻 |
| **② 数字/单位/货币 diff** | $/€ 不换、imperial/metric 不换、日期格式不换 | 脚本比对原文 vs 译文数字集合（确定性检查），差异处人工处理 |
