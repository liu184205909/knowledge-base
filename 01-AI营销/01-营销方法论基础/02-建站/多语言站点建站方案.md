# 多语言站点建站方案（B+D：Polylang + DeepL API）

> **定位**：英文主站扩展德/法/日等小语种市场的建站与内容架构方案
> **架构一句话**：Polylang 免费版管语言关联（薄层），DeepL API 在本地流水线翻译英文内容，页面走既有 Elementor 流水线创建
> **创建**：2026-08-26

---

## 一、架构总览

```
英文源内容（HTML/MD）
  → DeepL API 翻译（自带 key，glossary 术语表锁定）
  → 本地微调（TKD 换本地关键词 / 数字单位 diff）
  → 德语页面走 HTML→Elementor 流水线（创建时即德语，无插件翻译兼容坑）
  → Polylang 免费版：语言标记 + 英↔德页面关联 + hreflang 自动输出
```

**分工**：
- **DeepL（方案 D 的引擎）**：正文翻译。德语恰是 DeepL 最强语种；无幻觉、输出稳定；API 原生支持 **glossary 术语表**（核心产品词/品牌词在引擎层强制统一）；DeepL API Free 每月 50 万字符
- **Polylang（方案 B 的架构）**：只做语言元数据管理——语言标记、页面关联、hreflang、语言切换器。不装任何翻译引擎 addon，不碰 `_elementor_data` 翻译

---

## 二、DeepL 不能替代的两个工序

| 工序 | 为什么 DeepL 做不了 | 怎么做 |
|---|---|---|
| **① 本地关键词研究 → TKD** | DeepL 直译英文标题，产出的是"英文关键词的德语直译"，不是德国人真实搜索词。英文排名词 ≠ 德语搜索词 | DataForSEO `location_code=2276`（德国）查本地 SERP + 本地词根；**Title/Meta/H1/URL slug 必须用本地真实搜索词**，正文可用 DeepL 翻译 |
| **② 数字/单位/货币 diff** | DeepL 不做单位换算：$/€ 不换、imperial/metric 不换、日期格式不换 | 脚本比对原文数字集合 vs 译文数字集合（确定性检查），差异处人工处理 |

---

## 三、试点单页操作清单（5 步）

1. **本地关键词定 TKD**：德语种子词 → DataForSEO 德国 SERP → 定 Title/Meta/H1/slug
2. **DeepL 翻正文**：英文源 HTML → DeepL API（挂 glossary 术语表）→ 德语 HTML；数字单位 diff 脚本过一遍
3. **WP 装 Polylang 免费版**：添加德语语言，URL 选 `/de/` 前缀
4. **创建德语页面**：HTML→Elementor 流水线；试点单页 wp-admin 手动关联英↔德页面
5. **界面字符串**（导航/按钮/footer）：Polylang 字符串翻译后台手填

## 四、规模化增补

- **REST 自动化**：Polylang 免费版 REST 不支持 `lang` 参数（Pro 功能），functions.php 加 glue code——`rest_insert_post` hook 调 `pll_set_post_language( $post_id, 'de' )` + `pll_save_post_translations()`（约 20 行）
- **上线策略**：先翻 GSC 已验证有流量的英文页 top 20（非全站一键），观察 6-8 周再加量——保持翻译页占全站合理比例
- **GSC**：添加目标国家定位
- **演进路径**：Polylang 单站（几十页）→ /de/ 独立 WP（德语站成型后拆站，彻底解耦）
