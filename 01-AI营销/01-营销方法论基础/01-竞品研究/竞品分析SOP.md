# 竞品分析 SOP（sitemap 深度研究）v3.0

> **适用**：任何品类/行业的竞品深度研究，及研究后的本地内容工程落地（第六节）
> **核心原则**：**URL slug 本身就是信息**（页面主题/类型/层级/pSEO 引擎），足够推断架构+内容主题，**不需要读页面正文**
> **v3.0 说明**（2026-08-24 重构）：合并 v2 的补丁式增补（§三防坑/§四踩坑/§八纪律散落三处）为单一"执行纪律"层；新增第二节"产出标准"（每竞对一份文档等硬性要求前置）；新增第五节"博客矩阵→选题转化"。流程未变，纪律收紧。
> **操作纪律**（禁子 agent / sample≤20 / 不读正文等）见 memory `competitor-research-toolchain`

---

## 一、流程（6 步）

1. **SERP 发现竞对（多词族纪律，2026-08-25 新增）**：DataForSEO 至少扫**三类词族**——①品类词 3-5 个（{产品} replacement/custom 等）②**工具/计价词 5-10 个**（{产品} calculator / instant quote / price calculator / quote online / order online——靠垫项目教训：第一轮只用品类词漏掉 8 家在线计价竞对，工具型玩家只从计价词浮出）③场景/长尾词 2-3 个。每词 top20-30，过滤大平台和 OEM 官网。**发现即全量深档——不按主观"对标价值"筛选**（用户原则 2026-08-25：每一个真实竞争对手都值得深度研究，筛选=信息损失）。补充发现渠道：**基建反推法**（SaaS Referral 榜反查客户名单，能发现未做 SEO 但已在赚钱的站，见选品方法论 04-竞品与社区逆向挖掘法 §2.4）
2. **定位 sitemap**：读 `{domain}/robots.txt` 找 `Sitemap:` 声明（权威，不猜 URL）；无声明再试常规路径
3. **完整提取并留档**：Python 全量提取 `<loc>`（递归 sitemap index）。**必须全量不抽样**；**raw json 永久留档在 `{项目}/竞品研究/站点sitemap数据/`（非 tmp 语义目录）**——重抓≠原数据（口径漂移无法归因）
4. **slug 三维度分析**：机器算分布（页型/模式/lastmod），LLM 只看统计结果做判读，不把全部 URL 放进 context
5. **产出竞对文档**：**10 家对比总表 1 份 + 每竞对独立深度文档 10 份**（结构见第二节）——每家一份是硬性要求，不得以"总表小节"替代
6. **博客矩阵→选题转化**：对**所有含博客的竞品**（Python 全量核实，不得凭印象）做主题矩阵，转化为自己站的文章选题清单（规则见第五节）

## 二、产出标准（每竞对文档八节，缺一即未完成）

> **执行纪律**：动笔前把本节八项抄成 checklist 逐项打勾。SOP 写了八个维度，执行者最容易只做一级目录统计就交差——"最低限度交差"是最大风险。

每竞对文档（`竞品研究/竞品站点/{domain}.md`，300-500 行，Python 真实统计）：

1. **档案头**：域名/平台（sitemap 分段判定）/URL 总数/流量/SERP 表现/活跃度
2. **信息架构 IA**（路径维度）：目录层级树+顶级导航推断
3. **pSEO 引擎**（模式维度）：核心 slug 模式+维度组合 DNA+代表 URL 样本 10 条
4. **页型分布**（分布维度）：**页型级**分类（产品/类目/博客 post/静态 page/工具页/教程页），跨站统一口径可对比；区分真 SEO 页 vs SKU 长尾 vs tag 归档
5. **page vs post 判定**：竞品固定层级页 vs 流式内容分布→自建 WP 架构映射
6. **更新重心**：lastmod 月度分布→近期动作
7. **特有情报**：该竞品独有的结构资产/模式（每家定制深挖，非模板填充）
8. **可抄/可超/须避**三清单（各 2-3 条，数据佐证）

另产 1 份 `竞品研究/00-对比总表.md`（10 家：域名/平台/URL 数/pSEO 引擎/页型分布/SERP/流量）+ **1 份《竞对决策级发现总汇》**（2026-08-24 新增，靠垫项目教训）：
7. **决策级发现总汇**（四级漏斗的独立综合层，不可隐式散落）：§行业格局判断（5-8条决策级发现+支撑档案+我方对应决策）｜§分战场发现（流量/产品/内容）｜**§决策溯源表（核心：我方每个战略决策←支撑它的竞对发现，建站后复盘与第二项目复用的证据回查载体）**｜§空白与机会｜§档案索引——产出时机：全部深档完成后、进战略层（内容策略/网站结构）之前

**完整范式（四级漏斗+三工序执行层，2026-08-24 用户定案）**：
```
研究层（竞对独立深档）→ 综合决策层（发现总汇+决策溯源）→ 战略层（内容策略+网站结构设计）
  → 执行层（三道工序，有依赖顺序）：
     ① 网站规划（URL底册/导航契约/页面清单——定放什么页什么层级）
     ② 网站页面内容规划（每页区块/内容/转化路径原型——①定了URL才能做内链）
     ③ 文章内容生产（Brief/词量档/内链矩阵——②定了转化路径才能接CTA）
```

## 三、slug 三维度（方法论核心）

| 维度 | 看什么 | 得出什么 |
|------|--------|---------|
| **路径** | URL 目录层级 | 信息架构 IA（顶级导航/子聚合/页型前缀） |
| **模式** | slug 命名规律 | pSEO 引擎 DNA（维度组合） |
| **分布** | 每类 url_count 占比 | 战略重心（产品/内容/pSEO/本地哪个驱动） |

**常见 slug 模式 → pSEO 引擎对照**（跨行业）：

| slug 模式 | pSEO 引擎 | 例子 |
|----------|----------|------|
| `/{属性A}-{属性B}-{核心词}/` | 双属性映射 | `/apple-iphone-15-case/` |
| `/{规格A}/{规格B}/{规格C}/` | 多维规格笛卡尔积 | `/shoes/running/mens/size-10/` |
| `/{实体}-for-{场景}/` | 场景导航 | `/crystals-for-sleep/` |
| `/{实体}-vs-{实体}/` | 对比页 | `/shopify-vs-woocommerce/` |
| `/{实体}-alternatives/` | 替代页 | `/salesforce-alternatives/` |
| `/{地区}/{核心词}/` | 地理 pSEO | `/plumber-chicago-il/` |

**分布 → 战略重心**：产品页占大头=产品驱动｜博客/术语库占大头=内容驱动（产品页只转化）｜pSEO 规格页占大头=pSEO 驱动｜地理页占大头=本地 SEO 驱动
**流量修正**：吃流量最多的页型 ≠ 页数最多的页型时，战略重心以流量数据为准（slug 分布只是供给面）

**从 slug 能得到什么**：信息架构｜页型分布｜pSEO 引擎｜内容主题矩阵（实体×属性×场景×地区）｜战略重心｜规模与质量信号（某类页大量 404=堆砌已废弃）｜更新重心（lastmod）｜国际化战略（语言分段）

## 四、执行纪律（三组踩坑整合，全部实战换来的）

### 4.1 执行质量
1. **动笔前 checklist**：第二节八项抄成清单逐项打勾，缺一项=没做完（不是"做过了"）
2. **补救模式固定**：被质询后深挖必须 (a) 回 raw 重新统计而非凭记忆 (b) 推翻旧结论在原处显式标注 (c) 补出的维度进正文编号序列——否则文档读起来自洽实际矛盾
3. **审查 agent 是标配**：>10 家竞品或 >100 页产出，完成后跑一轮 adversarial 合规审查（对照 SOP 逐项+数据对账）
4. **全量核实不凭印象**："几家有博客/几家有工具"这类范围判断必须 Python 扫全量 sitemap 得出——凭印象说"5 家"漏 3 家是真实事故

### 4.2 数据与工具
5. **raw 永久留档**（见流程 3）：tmp 只装自己的计算过程；外部事实记录进研究目录。脚本规范：`{n, urls_all, d1_full, d2_full}` 全进 raw
6. **端点先探测**：任何新 API 端点先单次探测确认 status_code=20000 再进脚本（DFS keywords_for_domain 曾 404 两轮跑空）
7. **Ubersuggest MCP 是 user-scope OAuth，子 agent 不可见**：主会话先查喂进 prompt，或用 DFS Labs 替代并标注口径缺口
8. **429 断点续跑**：任务幂等（断点检查已产出→跳过）；等待递增 60s→3min→5min
9. **敏感词在脚本层过滤**：竞对关键词里的敏感地缘词会让 agent 会话被杀——只计数不落词面

### 4.3 判读口径
10. **页型级不是目录级**：必须归纳到跨站统一页型分类；工具页（calculator/planner/quiz/converter/finder/map/checker/simulator/booking/estimate）单独归类——漏扫=漏掉一整条产品线。**工具/计价能力判定不能只看 sitemap**（2026-08-25 教训：patiolane/rofielty 的配置器嵌在 PDP/类目页，sitemap 零痕迹——判定=SERP 计价词族命中 + webReader 实抓确认"输入尺寸→出价格"交互；纯 RFQ 询盘不算在线计价）
10b. **特殊价值竞对的增强研究层（2026-08-25 新增）**：与己方**同模式**的竞对（同供应链结构/同打法，如 rofielty=中国供应链 DTC）价值高于普通对标——常规八节深档之外追加"模式级深研"（商业模式七维度：品类定价战略/配置维度全集/信任构建/物流交付/营销冷启动/技术栈证据链），产出"它已解决而我方空白的能力清单+可抄战术"
10c. **定价情报源不止配置器（2026-08-25 新增）**：B2B 计算器（成本结构外泄，如 triad MSRP 报价器——passcode 锁可剥离 DOM 留存逻辑本地重放）、工厂公开价表（如 foamite 的 $/bf 表）、死代码变量——遇则采，交叉验证己方成本假设
11. **一词实测≠词群结论**：每页型至少 8-16 词 SERP 实测再下结论
12. **AI 抗性分页型统计**：单值静态映射词与多值决策词在 AIO 时代命运不同，不能全站一个平均数
13. **跨词变体意图归并**：变体各自显示全量 vol 虚高 10-20 倍，归并后再判量级
14. **平台识别看源码不猜**：curl 看 generator meta/静态资源域名；XML 转义（`&lt;loc&gt;`/CDATA）和 `image:loc` 与 `loc` 混块要用分块提取兼容
15. **研究→生产闭环**：每个研究结论（页型/词群/写法）必须能指到生产侧对应物（模板/排产/质检断言）——没有下游指向的结论等于白研究

## 五、博客矩阵 → 选题转化（流程 6 的执行规则）

> 适用对象：**全部含博客的竞品**（用 `/blog|/learning-center|/news|/journal|/resources|/articles` 正则 Python 全量扫 sitemap 得出清单，不凭印象）

1. **拆子集**：每家博客 URL 拆出 `{domain}_blog_split.json`（`{分组: [urls]}`）落 `站点sitemap数据/`
2. **主题聚类**：统一主题轴（测量教程/选购对比/材质面料/养护清洁/DIY/品牌替换/行业应用/其他）聚类每家
3. **主题×竞对矩阵**：行为主题、列为竞品家的篇数矩阵，标出"多家都有但量少"（可超越）与"零覆盖"（空白）
4. **对位自己**：读自己 `posts/`（或文章/）已有 slug，标三档：已覆盖对位/竞品有我无/全空白
5. **选题清单产出**：按 竞品验证强度（多家有=需求实证）+ 差异化空间 排序，产出 20-30 个 slug 级选题（含建议词量），落 `竞品研究/01-博客主题矩阵与选题转化.md`
7. **"其他"类 >30% 须二次细分**：聚类后"其他"占比超三成说明主题轴不够用，回到 slug 细分再聚类
8. **三家阈值定优先级**：某主题 ≥3 家覆盖=需求实证（P0）；1-2 家=验证弱（P1）；零覆盖=空白（P2，需自证需求）
7. **判读红线**：内容驱动站若主题与购买意图零交集（如 foamfactory 215 篇摊 9 个无关域），它是反例不是学习对象——学习对象看**词族集中度**（zipcushions 博客 100% 聚焦商业线）

## 六、研究之后的落地：本地内容工程 → 建站最后一步

> **核心原则**：研究产出引擎/词池/框架后，**内容与建站解耦**。全部产物先本地文件化，建站（WP+Woo）只是最后的"导入"动作。
> **C 端技术栈铁律**：C 端站统一 **WordPress+WooCommerce**（竞品用 Shopify 也不跟随），见 memory `c-end-wp-woo-stack`
> **page 导入铁律**：page 走 HTML→Elementor JSON 流水线（见建站 SOP《HTML转Elementor混合流水线SOP》），**禁止 REST 塞 HTML**；post 走 MD→Gutenberg

| 步骤 | 产物 | 位置 |
|------|------|------|
| 1. 站点结构 | url-map（全站 URL 底册）/nav（IA，含可视化 HTML） | `站点结构/` |
| 2. 数据层 | 词池/实体 JSON（机器可读，页面生成真源） | `数据/` |
| 3. pSEO 页面 | HTML（目录名=URL slug，全页原型） | `页面原型/` |
| 4. 博客文章 | MD（front matter+四层矩阵） | `文章/` |
| 5. **建站（最后）** | WP 装机→page 走 Elementor 流水线/post 走 REST→Rank Math | 服务器 |

**页面契约（HTML）**：目录名=URL slug；TKD 齐全；schema 按页型组合；内链尾斜杠
**文章契约（MD）**：文件名=slug；YAML front matter（title/desc/date/tag/wordcount）；H1 一次；内链尾斜杠；每篇 ≥1 产品页内链；词量按层（how-to 2000+/gift guide 1800+/科普 1500+）
**生产纪律**：数据驱动（data/ JSON 生成底座，每页文字差异化）；事实零错（数据/价格逐项核对）；agent 分工防冲突（独立目录/文件）；建站前全量本地质检，线上验证只做一次

## 七、流量交叉验证（Ubersuggest MCP）

> slug 分析是**供给侧推断**（建了什么页面）；关键词/流量数据是**需求侧验证**（什么在吃流量）。单看 sitemap 只知道"有什么"，交叉才知道"什么有效"。

| Ubersuggest 工具 | 验证什么 | 配合本 SOP 哪步 |
|------|---------|----------------|
| `domain_overview` | 规模分级（关键词数/DA/月流量）+ 24 个月趋势 | 流程 1 竞对筛选：增长站=学习对象，衰退站=切入窗口 |
| `domain_keywords` | 竞品实际吃词 top N（词/排名/流量贡献/落地 URL） | 验证流程 4 推断的 pSEO 引擎是否真在吃流量 |
| `domain_top_pages` | 哪类页面在吃流量（产品/博客/pSEO） | 修正"分布→战略重心"结论 |
| `backlink_opportunity` | 链到竞品但不链自己的 referring domains | 顺产外链建设清单 |

**交叉判读**：
- 有页面无排名 = 无效堆砌（抄结构别抄这个）
- slug 模式 + 对应词有排名 = 引擎已验证，直接复用
- 吃流量最多的页型 ≠ 页数最多的页型 = 战略重心以流量数据为准（slug 分布只是供给面）
- 流量趋势陡降 = 竞品衰退，切入窗口

**纪律**：
- SERP 竞对发现**只用 DataForSEO**（铁律不变）；volume/KD 主源 SEMrush（Seed-Master），Ubersuggest 是第二交叉源
- 150 次/天全局额度：10 家竞品 × 2-3 查询 ≈ 20-30 次，研究阶段够用
- 小站常 noData 属正常非故障；自家站真实数据以 GSC 为准
- user-scope OAuth 子 agent 不可见（见 §四.7）；替代口径 DFS Labs domain_rank_overview 并标注缺口

## 八、方法边界

| 场景 | 方法 |
|------|------|
| 竞品架构+内容主题分析 | **本 SOP**（slug 三维度） |
| 流量/关键词验证 | Ubersuggest MCP（§七）；SEMrush 主源 |
| 单页内容/UX 深拆 | webReader / Playwright |
| **深档（八节结构分析）** | **禁 Playwright**——sitemap 全量+slug 统计+curl 判平台+webReader 单页兜底（2026-08-25 用户纪律：浏览器自动化只用于测价等交互必需场景） |
| 配置器测价/动态价 | Playwright 单变量回归（JS 价唯一获取通道） |
| backlink/技术 SEO 审计 | Ubersuggest backlinks（快筛）/ Screaming Frog（深审） |

**不可替代价值**：不爬全站、不读页面正文，用 URL 结构反推信息架构/pSEO 引擎/内容矩阵/战略重心——成本最低、信息密度最高。
