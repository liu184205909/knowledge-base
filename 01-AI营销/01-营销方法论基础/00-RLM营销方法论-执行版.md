# RLM营销方法论 - AI执行版

> **核心原则**：本版包含**决策骨架 + 项目实证 How + 字段定义**，可直接操作新项目。
>
> **使用方式**：AI 执行 RLM 项目时默认只读本文件（含字段定义 + 决策规则）。需要工具操作时查 `02-自动化工具库/`。

---

## 1. RLM 是什么

**RLM = 用 AI 的分而治之思想 + 从网站架构到内容全面超越竞品的策略，实现营销全流程自动化**。

默认服务于海外市场（B2B 外贸、B2C 独立站、SaaS/工具站、内容/Affiliate）。

核心逻辑：**模仿 + 超越 + 差异化**——先看市场上谁做得好 → 判断为什么好 → 找到没做好的地方 → 设计更快、更系统、更低成本的方案。

---

## 2. AI 执行纪律

**违反以下任一条即输出不合格**：

1. **不编造、不预测**：没有来源的数据标"待验证"，不虚构搜索量、流量、KD、CPC、收入、排名、转化率。用户画像必须有竞品/关键词/FAQ/评论等推导依据，依据不足标"初步推测"。
2. **不输出空泛策略**：模仿/超越/差异化必须具体到竞品、页面、内容、结构、关键词或转化路径。禁止"提升品牌力""优化用户体验"等无动作表述。
3. **输出必须可落地**：每次输出有明确文件名和路径；每阶段交付物能作为下一步输入；仅停留在分析时补任务清单或验收项。
4. **不一次性输出大而全**：先写 spec（规格/框架），拆成小块，逐步实现，持续测试，每步 review。AI 越强，流程反而越要保守。

> **让 AI 泼冷水**：向 AI 提问时，不问"这想法怎么样"，问"这想法最可能在哪里崩"。AI 最大的危险是用同样的热情帮一个烂想法做到产品级。

## 3. 启动准备

项目开始时创建本地项目文件夹（§3.2）和 Google Sheets 数据底座（§3.1）。产品、市场等信息从竞品和项目上下文自然产生，不单独填表。

### 3.1 数据底座（4 张表 + 字段速查）

| 表格 | 职责 | 创建时机 | 核心字段（保留列） |
|------|------|---------|-----------------|
| **竞品清单** | 竞品总表 | §3 启动 | 编号 / 网址 / 类型（直接/内容/间接）/ 建站平台 / AS / Organic Traffic / 月访问量 / 渠道拆分 / 深度拆解链接 |
| **Seed-Master** | 关键词主表 | 步骤 1B | Keyword / 中文 / Entity / Subtopic / Content Role / Volume / KD / CPC / Number of Results / Intent / Status（Candidate→Approved→In Content Plan→Skip） |
| **TopPages_All + TopKeywords_All** | 竞品 SEO 明细 | 步骤 1B | **TopPages**：URL / Traffic(%) / Traffic / Top Keyword / Primary Intent / LLM Prompts<br>**TopKeywords**：Keyword / Search Volume / KD / CPC / URL / Traffic / Traffic(%) / Number of Results / Keyword Intents |
| **内容清单** | 选题草案 + 执行池 | 步骤 1H 后 | 目标关键词 / Volume / KD / CPC / 搜索意图 / 内容类型 / 对应 URL / 竞品验证状态 / 建议发布节奏 / Brief 状态 |

> **实际执行规模建议**（基于水晶项目实证 + 独立审核）：
> - **竞品清单**：初期 30-40 家。分类按实际竞品分布来定（执行版 §4 步骤 1 的 1A 只分直接/内容/间接三类）——有些品类可能几十家全是直接竞品，有些可能直接竞品只有 5-10 家需要扩展到内容/间接竞品找机会。**分类是结果不是前提，不要预设框架**
> - **1D 深拆**：从清单中精简到 **10-15 家核心竞品**，不需要全做——1D 是一次性资产库，2B 决策遇到"不知道该不该做"时按需补做
> - **TopPages/TopKeywords**：查 **10-15 家核心竞品**，不全量导出
> - **Seed-Master**：**可分阶段建**（先核心 Topic Pillar 5-10K，后续主题扩展时补充），但不能改为纯按需查询——全量库是 Topic Discovery 的基础（水晶项目 Dreams 主题 755 篇就是从 Seed-Master 全量库中发现的）
> - **内容清单**：首批控制在 **100-200 条**（三源验证后），不要一次性 700+ 条草案未裁剪

> **字段细则**（SEMrush 导出删除列规则、字段标注时机、Status 生命周期）见 `01-竞品研究/1B数据处理工具手册.md`。
>
> **AI 接手时先验证数据底座存在**：通过 Google Workspace MCP 搜索对应项目文件夹、遍历本地项目文件夹，与项目简报索引比对，不一致以实际为准更新索引。

## 4. RLM 五步执行流程

### 步骤 1：竞品查找与分析

**目标**：找到所有相关竞品，建立数据基础，为步骤 2/3 提供**参考库**（不是决策链输入）。

> **实证定位**：步骤 1 产出的是**参考库**，不是后续每个页面/每篇文章都要回查的输入。1D 深度拆解是一次性资产库，2C/3.x 按需查询不重新拆解。

**子阶段框架**（每个 2-3 行：目标 + 关键输出）：

| 子阶段 | 目标 | 关键输出 |
|-------|------|---------|
| **1A 竞品发现** | 人工 Google 搜索 + SEMrush Organic Competitors 双轨道 | 竞品清单（直接/内容/间接三类） |
| **1B 多源数据采集** | 5 轨道并行：竞品清单数据 / Seed-Master 关键词池 / TopPages+TopKeywords / Seed-Master 证据增强 / Sitemap 解析 | 更新后的竞品清单 + Seed-Master + `TopKeywords_All` + `TopPages_All` + Sitemap 报告 |
| **1C 关键词研究验证** | 把 Seed-Master 从"可用数据表"转成"可决策关键词表"：验证 Entity/Subtopic/Content Role、补充 Business Relevance/Priority/Page Type | Seed-Master（1C 策略标注后）+ `关键词分组与优先级.md` |
| **1D 竞品深度拆解** | 每个核心竞品逐个拆解：靠什么拿流量、建了什么、覆盖/遗漏什么 | `1D-竞品深度拆解/竞品名称.md` × N + §9 候选策略点 |
| **1E 网站结构分析** | 跨竞品结构对比：导航、URL、分类模式、页面类型频率、SEO 价值 | 结构对比 + 分类/URL 命名观察 + 候选模仿点（→ 1H） |
| **1F 内容策略分析** | 内容类型、优势、缺口、共同弱点识别 | 内容策略分析（→ 1H） |
| **1G 用户画像** | 基于关键词意图 + 竞品观察 + FAQ 推导用户画像 | 用户画像（每个画像可追溯到证据） |
| **1H 策略清单** | 汇总 1D §9、1E、1F 候选 + 1G 画像，去重排序映射到页面/内容 | **策略中枢**：模仿清单 / 超越清单 / 差异化清单 + 不做什么反向清单 |

> **1A 搜索排除语法**（复制即用）：
> ```
> 关键词 -amazon.com -ebay.com -etsy.com -walmart.com -pinterest.com -reddit.com -youtube.com -facebook.com -tiktok.com -wikipedia.org -quora.com -target.com -aliexpress.com -alibaba.com
> ```
> AI 用 DataForSEO `serp_check` 时该语法无效，SOP 见 `1B数据处理工具手册.md`。

**边界约束**：
- 1D 数据输入按分析问题组合使用：核心输入（Top Pages + Top Keywords + Sitemap + Seed-Master + 轨道 D 证据）判机会；辅助输入（截图、渠道拆分）判背景。两者不混用。
- 1E/1F 输出"候选方向"语气（→ 1H 决策），不用"我们的策略"语气。
- 1H 是唯一完整策略中枢，不重复搬运竞品原始数据，只吸收候选策略点去重排序。

#### 1C 关键词研究核心 How（实证）

> 以下方法均在水晶项目 1C 阶段实际使用，证据见 `1C-关键词研究/` 目录。

**搜索意图分类 + 避开词清单**：
- Intent 字段标注：Informational / Commercial Investigation / Transactional / Navigational
- **避开词识别**：同关键词但意图偏移的词需标注避开（如 "dream house" 是电影不是房屋梦、"how to lucid dream" 是教程意图非内容意图）
- SERP 手动竞争度：对核心词查 top 20-30，识别"小博客进 top10 = 低 DR 可切入"、"Reddit/TikTok 进 AIO = 切入窗口"

**Splinter Method（关键词裂变）**：
- 复合词单页可命中多意图，对标竞品拆分结构
- 案例：`yellow snake spiritual meaning` / `black snake in house` / `venomous snake biting` 三个意图可被一个"蛇梦解析"主题承接

**关键词→页面类型映射**：
- 通过 `map_page_type.py` 或手工，将 Seed-Master 关键词映射到 37 种 Page Type（如 Article-Info / Product / Category-Hub / Tool / FAQ）
- 映射结果填入 Seed-Master `Recommended Page Type` 列

**优先级评分（5 维参考）**：
- Volume × KD 反向 × SERP 弱度 × 差异化价值 × 商业价值
- 简化版：直接按"高优先 / 中优先 / 长尾补全 / 避开"分层（具体标准按行业调整，不硬编码定义）

**倒漏斗策略（精简）**：
- BOFU（转化意图）→ MOFU（对比考察）→ TOFU（认知科普）
- B2C 独立站实证：TOFU 百科 + BOFU 功效混合首发（不严格 BOFU 优先），看品类特性调整

> 1B-1H 的字段定义、工具操作、模板见 §5 调用规则。

### 步骤 2：网站规划与建设

**目标**：基于 1E/1H 策略，规划并搭建网站核心页面。

#### 2A 架构规划

**关键输出**：网站结构 + URL 规则 + 内链规划 + 产品类目规划 + 核心页面内容规划 + **竞品页面频率矩阵**（2B 直接输入）。

> 原始证据（导航截图、URL 列表）留在 1E，2A 频率矩阵只保留决策摘要和引用。

#### 2B 页面决策（gate）

**没有通过 2B 决策的页面不能进入 2C**。

**强制输出 — 页面决策表**：

| 页面名称 | 页面类型 | 竞品覆盖率 | 对应竞品URL | 用户意图 | 1H策略匹配 | SEO/商业价值 | 实现复杂度 | 决策状态 | 执行批次 |
|---------|---------|-----------|------------|---------|-----------|------------|-----------|---------|---------|

**决策规则**：

| 竞品覆盖率 | 默认决策 | 例外 |
|-----------|---------|------|
| 75%+ | **必须做** | 与项目定位明显冲突时跳过 |
| 25-75% | **进入判断** | 看 1H 策略价值和资源成本 |
| <25% | **不做/远期** | 1H 明确要求的差异化页面除外（如差异化工具） |
| About/Contact/FAQ/Shipping/Returns | **业务必要** | 不受频率阈值支配，属信任基础 |

**执行批次**：B1a 上线骨架（首页/About/FAQ/Contact/产品模板） → B1b 核心 SEO 模板（百科单品/按意图分类等模板矩阵） → B2 上线后 1 月扩展 → B3 3 月内差异化 → B4 远期/模板工厂（需复审）。

#### 2C 逐页生成（三种生产模式）

**生产模式选择决策树**（必填，决定该主题线走哪条路径）：

```
判断条件                          → 生产模式            → 依据包要求
─────────────────────────────────────────────────────────────────────
≤30 篇 / 高价值转化页 / 1D 已深拆  → 精做模式            → 完整单页依据包
30-500 篇 / 同构矩阵 / 1D 抽样    → config-driven 模式   → 模板级依据包 + 字段表
500+ 篇 / 后期扩展 / 1D 缺失      → placeholder 模式    → 模板框架 + AI 段落 token + 批量差异化 QC
```

**三种模式共同要求**：
- **禁止占位文本**（Lorem ipsum / "Coming Soon"）
- **禁止图片复用**（关键视觉位每张独立 prompt）
- **依据可追溯**（基于上游证据 + 业务事实，不凭通用知识编造）
- **先依据后构建**（每个页面/主题线先完成依据包再写内容）
- **动态区数据源在构建时决定**（产品区/博客区等动态模块在构建阶段选定 shortcode/WP Query/REST，不用静态假卡片占位）

##### 精做模式 How（≤30 篇核心转化页）

**流程**：调用页面内容指南 → 建立单页依据包 → 写内容 → 图片资产清单 → 构建脚本

**单页依据包字段**：本页参考竞品 / 真实参考 URL / 上游来源索引（1D/1E/1H）/ 采用点 / 规避点 / 差异化点

**质量门禁**：单页 QC（依据完整性 + 内容质量 + 图片独立性 + Schema 校验）

##### config-driven 模式 How（30-500 篇同构矩阵）

> 水晶项目实证：tarot 690 篇 / numerology 21 篇 / zodiac-compatibility 78 篇 / chinese-zodiac 15 篇均走此模式。

**流程**：
1. **定义 knowledge base JSON**（如 `configs/tarot-knowledge.json`）：包含每篇文章的差异化字段（如塔罗牌的 archetype / element / keywords / 3 crystals / FAQ 4 问）
2. **写 generate.js 脚本**：读取 knowledge base + Brief 模板，批量生成文章 JSON（含 title/slug/excerpt/rank_math 三件套/完整 HTML/Schema）
3. **批量差异化 QC**（关键，防止 AI 批量生成雷同）：
   - **三道门禁**：
     - **独有判断测试**：每篇至少有 1 个竞品没有的判断（如"Amethyst 适合 XXX 的 3 个理由"）
     - **量化门禁**：相邻文章文本相似度 < 60%（用 N-gram 或 cosine）
     - **分级策略**：核心字段（如水晶推荐）必须有差异化，通用字段（如矿物学事实）可复用
   - **crystal-binding 检查**：水晶推荐必须有 source 字段（labyrinthos/soulfulnwild 等竞品来源），不能凭空生成
   - **FAQ 差异化**：同主题线的 FAQ 不能完全重叠
   - **forbidden-words 检查**：扫描品牌语调配置 §4 合规禁用词清单（heal/cure/guarantee/energy healing 等）
4. **批量上传**：`upload-post-content.js` + WP REST API（draft 状态）
5. **批量线上验证**：CJK 残留 grep / Schema 抽检 / dynamic_product_module 抽检

**模板级依据包字段**：字段结构定义 / 参考竞品（如 Labyrinthos + Biddy Tarot 2-3 家）/ 可复用语气 / 图片规则 / 实例页差异记录（不写完整 Brief，只填字段值差异）

##### placeholder 模式 How（500+ 篇后期扩展）

> 水晶项目实证：runes 24 篇 / animal-symbolism 26 篇 / mayan-zodiac 20 篇 / fengshui 47 篇 / spiritual 15 篇走此模式。

**流程**：
1. **定义 placeholder 模板**：每篇文章用 `@@@TOKEN@@@` 标记可替换段落（如 `@@@AI_EXPLAINED_INTRO@@@` / `@@@AI_MEANING_DEEP@@@` / `@@@AI_CRYSTAL_CITRINE@@@`）
2. **AI 批量生成 token 内容**：每个 token 单独 prompt AI 生成成品段落（不是占位符，是真实内容）
3. **fill-from-placeholders.js 注入**：脚本读取 placeholders-mainpages/*.txt + 模板，批量注入生成最终文章
4. **批量合规 + Schema 校验**（不做差异化 QC，因为内容本身就是 AI 生成的）：
   - forbidden-words 扫描（合规禁用词）
   - JSON-LD Schema 校验（Article / FAQPage / BreadcrumbList）
   - CJK 残留检查
   - 内链有效性检查

**模板框架字段**：H2/H3 结构 / 每 token 的写作要求 / 合规边界 / Schema 模板

**风险提示**：placeholder 模式生产的内容是 AI 原生生成，未走完整 Brief 流程。**只用于低竞争长尾扩展**，不用于核心转化页。Google 可能识别为 thin content，需监控收录率和排名。

#### 2D 上传与前端验收

**核心规则**：
- **单页试点先行**：第一个页面必须走完全闭环（生成→图片→上传→前端验收），验证通过再批量推进
- 逐页闭环，不做完当前页面不开始下一个
- **前端验收必须打开 preview URL 确认**，不能只看 API 返回 200
- **动态内容必须接真实数据源**（不用虚拟产品卡/虚拟文章卡/Lorem ipsum 冒充）

**验收清单**（每页上传后必过）：HTTP 200 + canonical / Title+Meta+H1 含目标关键词 / 导航可达 / 移动端首屏无横向滚动 / 动态区接真实数据 / 图片 webp+alt 完整 / 内链 3-5 条 / JSON-LD Schema 通过。

**批量上传技术执行前置**（实证踩坑清单）：
- **slug 规范**：`chakras-crystals` vs `chakra-crystals` 容易混淆，需在 2A 统一命名
- **title 长度**：≤60 字符（天使号码 title 易超）
- **prev/next 链接语言**：批量生成时易出现 CJK 残留（如 horoscope 144 篇 prev/next 中文）
- **future post 不要改 date**：会卡住排期
- **WooCommerce 产品分类**：dynamic_product_module 必须接真实 `product_categories`，不能用静态卡片
- **图片 URL 回写**：先生成/上传图片→拿 wp_id→回写到 article JSON→再上传文章
- **draft 批量上传后**：抽检 10% 打开 preview URL 验收

**排期发布**：
- `schedule-crystal-posts.js` 每天 3 篇，9-21 点随机时间
- future 状态排期，到日期自动 publish
- 跨类目交错发布（不让同主题线挤在同一周）

**线上验证**（发布后必做）：
- CJK 残留 grep（head 标签 / title / description / 内容）
- Schema 校验（Google Rich Results Test）
- featured_media 是否绑定
- 内链是否生效（打开文章看链接）
- dynamic_product_module 是否显示真实产品

> 详细操作见 §5 调用规则。

### 步骤 3：内容策略与内容营销

**定位**：本节是**控制面 + 实用 How**。社媒分发见 `04-社媒内容分发/社媒内容分发工作流.md`（项目内容稳定后启动）。

**跨步骤依赖**：内容清单草案可先启动；最终 URL、承接页面、内链规则、内容 Brief 需等步骤 2（2A+2B）完成后锁定或复核。

#### 3.0 内容优先目标

项目启动时按当前状态选择默认优先目标：

| 项目状态 | 内容优先目标 | 不优先做 |
|---------|------------|---------|
| 新站/冷启动 | 收录 + 排名基础 | 转化型复杂内容 |
| 有流量无转化 | 转化 + 信任建设 | 盲目扩更多选题 |
| 品类竞争激烈 | 差异化 + E-E-A-T | 普通泛科普 |
| 已有权威内容 | AI Citation + 外部分发 | 只做站内新增 |

#### 3.1 内容清单与批次

**核心原则：一次性做草案，分批进入正式 Brief**。

- 内容清单分两层：**执行清单**（首批完整字段）+ **候选池**（轻量字段，等批次轮到再补）
- 草案可一次性生成，正式 Brief 必须在数据补齐后锁定（KD/CPC、竞品验证、URL、内链规则）
- 用"发布节奏"代替"优先级"，每篇标注建议发布顺序

**三源验证原则**（选题必过）：
- 篇数/选题必须**竞品 sitemap**（1B 35 家）+ **Seed-Master volume** + **SERP 生态**三源交叉定，非策略粗估
- 案例：MBTI×水晶选题被三源证伪（搜索量低 + SERP 全小站 + 无竞品做），不进执行清单

**批次规划原则**：

| 原则 | 说明 |
|------|------|
| 先核心后扩展 | 首批覆盖核心 Topic Pillar 高价值关键词 |
| 按意图分层 | 每批包含不同意图类型，验证意图→内容匹配 |
| 批次大小 | 每批 10-30 篇 |
| 验证门槛 | 首批发布后观察 2-4 周，有收录排名信号再启动下一批 |
| 主题集中 | 单批不跨太多 Pillar |

**内容清单字段**：目标关键词 / Volume / KD / CPC / 搜索意图 / 内容类型 / 对应 URL / 竞品验证状态 / 建议发布节奏 / Brief 状态。

**选题确定后 → SERP 分析产出文章框架**（Brief 锁定前置，不可跳过）

> 这是 config/placeholder 模式最容易跳过的一步。跳过 = 预设结构而非 SERP 驱动 = "头重脚轻"的根因。

**5 步操作**：
1. **查这个词的 SERP top 10**（用 `serp_check` 或 webReader 抓取）
2. **分析文章类型**：百科？对比？教程？选购指南？——决定你的文章走哪种类型
3. **合并 H2/H3 结构**：提取 top 10 的子标题 → 找共识结构（它们都覆盖什么）→ 这是"基本盘"
4. **找共同缺口**：它们都没写什么？——这是你的**差异化机会**（来自 1F 内容缺口分析）
5. **产出文章框架**：合并的结构 + 差异化角度 → 一份 H1/H2/H3 骨架（不是完整 Brief，是结构模板）

**三种模式的最低要求**：
- **精做模式**：每篇文章都走这 5 步，产出单页框架
- **config-driven 模式**：主题线首批 3-5 篇走这 5 步定义模板框架，后续批量复用
- **placeholder 模式**：至少走步骤 1-2 确认文章类型，不能纯靠 AI 生成结构

**产出文件**：`03-内容策略/文章框架/{主题线}-框架.md`（如水晶项目的 `模板-Crystal-Meaning文章框架.md`）

#### 3.2 Brief 锁定门槛

**Brief 锁定是内容从"规划"进入"生产"的 gate**。

**锁定门槛**（全部满足才能锁定）：

| 门槛项 | 要求 |
|--------|------|
| 关键词与意图校验 | Brief 声明目标关键词、搜索意图、数据来源、结构依据。模板化实体页可"框架级关键词校准 + 单篇轻量检查"；非模板化长文需补单篇关键词证据 |
| 关键词数据完整 | 目标关键词已有 Volume/KD/CPC/意图标注 |
| 竞品验证完成 | 至少 2-3 篇竞品内容已复核（覆盖结构和关键论点） |
| URL 和承接页面确定 | 步骤 2B 已决策 |
| 内链规则明确 | 与已有内容的内链关系已规划 |
| 选题角度差异化 | DREAM 检查至少一项结构/视角/信息增量差异 |

**DREAM 模型 — Brief 角度检查**：

| 维度 | Brief 中对应的检查 | 未覆盖时的风险 |
|------|------------------|-------------|
| **D** — Demand（需求） | H2 是否说明了"为什么需要" | 用户看不到相关性 |
| **R** — Reason（理由） | 是否给出"为什么选这个" | 用户无法做比较 |
| **E** — Evidence（证据） | 是否有数据/案例/来源支撑 | 信任不足，AI 不引用 |
| **A** — Advantages（优势） | 是否展示了具体差异化 | 淹没在同质内容中 |
| **M** — Motivation（动机） | 是否给了"现在行动"的理由 | 流量不转化 |

> DREAM 可直接嵌入 Brief 大纲：H2 需求场景（D）→ H3 理由（R）→ H3 证据（E）→ H2 优势（A）→ H2 行动动机（M）。

**Brief 不合格 4 表现**（出现任一即打回）：
1. 关键词堆砌，意图不匹配
2. 大段通用科普，无信息增量
3. 无差异化角度，与竞品同质
4. CTA 缺失或与内容脱节

**Brief 字段表**（每篇文章一份，存放在 `03-内容策略/内容Brief/文章A-Brief.md`）：

| 字段 | 内容 |
|------|------|
| 基本信息 | 目标关键词 / 搜索意图 / 内容类型 / 目标用户 / 建议发布节奏 |
| 写作目标 | 这篇文章解决什么问题，服务哪个转化目标 |
| 参考竞品 | 2-3 篇竞品文章 URL |
| 竞品观察 | 竞品已覆盖（列点）/ 竞品未覆盖（缺口） |
| 差异化角度 | 这篇如何比竞品更完整/更清楚/更有实用价值 |
| 推荐大纲 | H1 + 3-5 个 H2（DREAM 嵌入：H2 需求场景→H3 理由→H3 证据→H2 优势→H2 行动动机） |
| 必须包含的信息 | 3-5 个关键信息点 |
| 素材证据来源 | 一手素材（产品经验）/ 竞品观察 / 竞品段落素材（Top 10-20 评分）/ 用户评论 / 研究数据（SEMrush Volume/KD） |
| 内链建议 | 链接到产品页/类目页/相关博客 3-5 条 |
| CTA 建议 | 询盘/下载/购买/订阅/联系销售 |

**GEO 内容优化要点**（提高 AI 引用率）：
- **AI 购物旅程定位**：开放调研 / 决策核查 / 使用支持
- **写作规则按问题类型**：推荐类（Top 3 结论前置）/ 对比类（表格+明确结论）/ 信任核查类（第三方评价优先）/ 解答类（FAQ answer-first）
- **内容结构**：FAQ 模块（FAQPage schema）/ answer-first / 品牌名自然 3-5 次 / 场景化描述 / 至少 1 个外部数据源

**品牌语调配置**：首次 Brief 锁定前完成定义（存放在项目 `03-内容策略/品牌语调配置.md`），Brief 引用配置不重复定义。

#### 3.3 内容生产边界 + 去 AI 化技术

**内容质量地板**（4 项，任一不满足即打回）：

| 质量项 | 要求 |
|--------|------|
| 一手观察 | 包含来自竞品复核、用户评论或原始数据的独特视角 |
| 信息增量 | 至少有一项竞品未覆盖的结构/视角/数据/案例 |
| 真实数据 | 关键论点有可追溯来源（不编造数据） |
| 未答之问 | 回应了 SERP 中用户明确提出但竞品未回答的问题 |

**七大 AI 写作特征识别**（精简版，前 4 条必查）：
1. **Pub Test 失败**：段落读起来像"任何博客都能发"，缺乏品牌声音
2. **First 10% Deletion**：开头 10% 是冗余引入，应直接给结论
3. **Kill List 命中**：含 AI 高频词（delve/leverage/tapestry/navigate/unveil 等）
4. **Human Sandwich 缺失**：没有"真人语气"夹击 AI 段落（如"我戴紫水晶睡觉一个月的变化"）
5. 模板化句式（"Not only... but also..."）
6. 过度抽象（无具体案例）
7. 平衡幻觉（"While X has benefits, Y is also good"）

**六大去 AI 化技术**（前 3 条核心）：
1. **First 10% Deletion**：删开头冗余，直接进结论（quick-answer blockquote 是落地形式）
2. **Kill List**：扫描禁用词清单（含合规向：heal/cure/guarantee；含 AI 风格向：delve/leverage/tapestry）
3. **Human Sandwich**：AI 生成的客观段落之间，夹入"真实使用体验 / 个人观察 / 品牌故事"
4. Pub Test（读出来像不像真人写的）
5. High-Low Technique（信息密度交替）
6. Anti-Pattern Prompting（用反例 prompt 让 AI 避开模板）

> 项目级禁用词清单见 `03-内容策略/品牌语调配置.md §4`。AI 风格词与合规词双轨管理。

**编辑完成检查清单**（实证 4 条）：
- [ ] 关键词与意图匹配
- [ ] 内链 3-5 条指向已有页面
- [ ] Meta 三件套（Title/Description/H1）含目标关键词
- [ ] 无 CJK 残留 + 无合规禁用词

> **规模化内容风险自查表 / Mount AI 崩塌数据 / Commodity Content 自检 / Google Scaled Content Abuse 红线** → 详见 `03-内容生产与质检/内容质量标准.md`

#### 3.4 发布前质检路由

**质检路由矩阵**：

| 检测项 \ 内容类型 | 百科/科普 | 对比/选购 | 教程/How-to | 转化型 | 工具 |
|-----------------|----------|----------|------------|--------|------|
| EEAT 质量评估 | ✅ 标准 | ✅ 加强 | ✅ 标准 | ✅ 轻量 | — |
| 站外原创性 | ⬜ 可选 | ✅ 必做 | ⬜ 可选 | ⬜ 跳过 | — |
| 站内重复 | ✅ 必做 | ✅ 必做 | ✅ 必做 | ✅ 必做¹ | — |
| GEO/AI Citation | ✅ 必做 | ⬜ 可选 | ⬜ 可选 | ⬜ 跳过 | — |
| Schema 类型 | ⬜ 可选 | ⬜ 可选 | ⬜ 可选 | ✅ 必做 | ✅ 必做 |

**通过标准**：DREAM 5 维至少覆盖 3 项 + 该内容类型"必做"项全通过 + 无 AI 化高风险段落 + 内链指向页面已存在。

**条件覆盖**：
- 若内容优先目标含"AI Citation"，所有站内内容至少做轻量 GEO 检查
- ¹ 模板化产品页、集合页、pSEO 批量页面**必做**站内重复检测

#### 3.5 发布与内链承接

**发布前检查**：URL 规则一致 / Meta 三件套完整 / 内链双向确认 / 图片已上传 / 分类标签正确。

**内链规则**：
- **上下层级**：百科页 → 分类页 → 产品页（如 Crystal Meaning → Crystal Category → Product）
- **主题关联**：同 Topic Pillar 下的内容互相链接
- **意图递进**：信息型 → 商业型 → 交易型（"什么是 X" → "最好的 X 推荐" → 产品页）
- **描述性锚文本**：用"X 的核心功效"而非"点击这里"
- **工具联动**：互动工具 CTA 双向链接（如文章 → Crystal Quiz，Quiz 结果 → 相关文章）
- **字段二次利用**：knowledge base 字段（如水晶推荐）在文章 / 工具 / Hub 页多处复用，保持单源

**内链建设**（簇内互链）：
- 同主题线文章互链（如 22 张大牌塔罗互相链接）
- Pillar 页汇总链接（如 `/crystals-for-anxiety/` 链接到相关水晶百科）
- 数据单源共享：`_shared/xxx-knowledge.json` 让多个工具/文章引用同一数据源

#### 3.6 复盘与放大（上线完成后启用）

**触发条件**：
- 首批发布后 4 周（有收录和初步排名信号）
- 单篇异常（30+ 天未进前 100，或跳出 > 80%）
- 批次完成（验证批次规划有效性）

**复盘范围**：选题模式 / 意图匹配 / 关键词表现 / 内容质量 / 用户行为

**资产沉淀**：高表现内容模式 → 项目复盘文档；已验证有效的竞品段落 → Brief 文档复用；关键词表现 → 1C/Seed-Master 回写
