# RLM营销方法论 - AI执行版

> **核心原则**：执行版只回答 **What + When + Why**，不回答 How。How 在 `02-自动化工具库/` 和 `03-模板库/`。
>
> **使用方式**：AI 执行 RLM 项目时默认只读本文件。需要模板、字段细则、工具操作时按 §5 调用规则按需加载配套文档。

---

## 1. RLM 是什么

**RLM = 用 AI 的分而治之思想 + 从网站架构到内容全面超越竞品的策略，实现营销全流程自动化**。

默认服务于海外市场（B2B 外贸、B2C 独立站、SaaS/工具站、内容/Affiliate）。

核心逻辑：**模仿 + 超越 + 差异化**——先看市场上谁做得好 → 判断为什么好 → 找到没做好的地方 → 设计更快、更系统、更低成本的方案。

---

## 2. AI 执行纪律

**违反以下任一条即输出不合格**：

1. **不编造、不预测**：没有来源的数据标"待验证"，不虚构搜索量、流量、KD、CPC、收入、排名、转化率。用户画像必须有竞品/关键词/FAQ/评论等推导依据，依据不足标"初步推测"。
2. **不输出空泛策略**：模仿/超越/差异化必须具体到竞品、页面、内容、结构、关键词或转化路径。禁止"提升品牌力""优化用户体验"等无动作表述。
3. **输出必须可落地**：每次输出有明确文件名和路径；每阶段交付物能作为下一步输入；仅停留在分析时补任务清单或验收项。
4. **不一次性输出大而全**：先写 spec（规格/框架），拆成小块，逐步实现，持续测试，每步 review。AI 越强，流程反而越要保守。

> **让 AI 泼冷水**：向 AI 提问时，不问"这想法怎么样"，问"这想法最可能在哪里崩"。AI 最大的危险是用同样的热情帮一个烂想法做到产品级。

## 3. 启动准备

项目开始时创建本地项目文件夹（§3.2）和 Google Sheets 数据底座（§3.1）。产品、市场等信息从竞品和项目上下文自然产生，不单独填表。

### 3.1 数据底座

项目启动时创建**竞品清单**，其余表格按步骤推进按需创建。

| 表格 | 职责 | 创建时机 |
|------|------|---------|
| **竞品清单** | 竞品总表（网址、类型、建站平台、AS、流量、深度拆解链接） | §3 启动 |
| **Seed-Master** | 关键词主表（按 Topic Pillar 分工作表，含 Volume/KD/CPC/意图/Entity/Subtopic/Content Role） | 步骤 1B |
| **TopPages_All + TopKeywords_All** | 竞品页面级和关键词级 SEO 明细 | 步骤 1B |
| **内容清单** | 选题草案 + 执行池（目标关键词、意图、内容类型、URL、Brief 状态） | 步骤 1H 后 |

> **AI 接手时先验证数据底座存在**：通过 Google Workspace MCP 搜索对应项目文件夹、遍历本地项目文件夹，与项目简报索引比对，不一致以实际为准更新索引。字段定义、SEMrush 导出删除列规则见 `02-自动化工具库/02-竞品研究工具/1B数据处理工具手册.md`。

## 4. RLM 五步执行流程

### 步骤 1：竞品查找与分析

**目标**：找到所有相关竞品，建立数据基础，为步骤 2/3 提供**参考库**（不是决策链输入）。

> **实证定位**：步骤 1 产出的是**参考库**，不是后续每个页面/每篇文章都要回查的输入。1D 深度拆解是一次性资产库，2C/3.x 按需查询不重新拆解。

**子阶段框架**（每个 2-3 行：目标 + 关键输出）：

| 子阶段 | 目标 | 关键输出 |
|-------|------|---------|
| **1A 竞品发现** | 人工 Google 搜索 + SEMrush Organic Competitors 双轨道 | 竞品清单（直接/内容/间接三类） |
| **1B 多源数据采集** | 5 轨道并行：竞品清单数据 / Seed-Master 关键词池 / TopPages+TopKeywords / Seed-Master 证据增强 / Sitemap 解析 | 更新后的竞品清单 + Seed-Master + `TopKeywords_All` + `TopPages_All` + Sitemap 报告 |
| **1C 关键词研究验证** | 把 Seed-Master 从"可用数据表"转成"可决策关键词表"：验证 Entity/Subtopic/Content Role、补充 Business Relevance/Priority/Page Type | Seed-Master（1C 策略标注后）+ `关键词分组与优先级.md` |
| **1D 竞品深度拆解** | 每个核心竞品逐个拆解：靠什么拿流量、建了什么、覆盖/遗漏什么 | `1D-竞品深度拆解/竞品名称.md` × N + §9 候选策略点 |
| **1E 网站结构分析** | 跨竞品结构对比：导航、URL、分类模式、页面类型频率、SEO 价值 | 结构对比 + 分类/URL 命名观察 + 候选模仿点（→ 1H） |
| **1F 内容策略分析** | 内容类型、优势、缺口、共同弱点识别 | 内容策略分析（→ 1H） |
| **1G 用户画像** | 基于关键词意图 + 竞品观察 + FAQ 推导用户画像 | 用户画像（每个画像可追溯到证据） |
| **1H 策略清单** | 汇总 1D §9、1E、1F 候选 + 1G 画像，去重排序映射到页面/内容 | **策略中枢**：模仿清单 / 超越清单 / 差异化清单 + 不做什么反向清单 |

> **1A 搜索排除语法**（复制即用）：
> ```
> 关键词 -amazon.com -ebay.com -etsy.com -walmart.com -pinterest.com -reddit.com -youtube.com -facebook.com -tiktok.com -wikipedia.org -quora.com -target.com -aliexpress.com -alibaba.com
> ```
> AI 用 DataForSEO `serp_check` 时该语法无效，SOP 见 `1B数据处理工具手册.md`。

**边界约束**：
- 1D 数据输入按分析问题组合使用：核心输入（Top Pages + Top Keywords + Sitemap + Seed-Master + 轨道 D 证据）判机会；辅助输入（截图、渠道拆分）判背景。两者不混用。
- 1E/1F 输出"候选方向"语气（→ 1H 决策），不用"我们的策略"语气。
- 1H 是唯一完整策略中枢，不重复搬运竞品原始数据，只吸收候选策略点去重排序。

> 1B-1H 的字段定义、工具操作、模板见 §5 调用规则。

### 步骤 2：网站规划与建设

**目标**：基于 1E/1H 策略，规划并搭建网站核心页面。

#### 2A 架构规划

**关键输出**：网站结构 + URL 规则 + 内链规划 + 产品类目规划 + 核心页面内容规划 + **竞品页面频率矩阵**（2B 直接输入）。

> 原始证据（导航截图、URL 列表）留在 1E，2A 频率矩阵只保留决策摘要和引用。

#### 2B 页面决策（gate）

**没有通过 2B 决策的页面不能进入 2C**。

**强制输出 — 页面决策表**：

| 页面名称 | 页面类型 | 竞品覆盖率 | 对应竞品URL | 用户意图 | 1H策略匹配 | SEO/商业价值 | 实现复杂度 | 决策状态 | 执行批次 |
|---------|---------|-----------|------------|---------|-----------|------------|-----------|---------|---------|

**决策规则**：

| 竞品覆盖率 | 默认决策 | 例外 |
|-----------|---------|------|
| 75%+ | **必须做** | 与项目定位明显冲突时跳过 |
| 25-75% | **进入判断** | 看 1H 策略价值和资源成本 |
| <25% | **不做/远期** | 1H 明确要求的差异化页面除外（如差异化工具） |
| About/Contact/FAQ/Shipping/Returns | **业务必要** | 不受频率阈值支配，属信任基础 |

**执行批次**：B1a 上线骨架（首页/About/FAQ/Contact/产品模板） → B1b 核心 SEO 模板（百科单品/按意图分类等模板矩阵） → B2 上线后 1 月扩展 → B3 3 月内差异化 → B4 远期/模板工厂（需复审）。

#### 2C 逐页生成（核心规则）

**生产模式选择决策树**（必填，决定该主题线走哪条路径）：

```
判断条件                          → 生产模式            → 依据包要求
─────────────────────────────────────────────────────────────────────
≤30 篇 / 高价值转化页 / 1D 已深拆  → 精做模式            → 完整单页依据包
30-500 篇 / 同构矩阵 / 1D 抽样    → config-driven 模式   → 模板级依据包 + 字段表
500+ 篇 / 后期扩展 / 1D 缺失      → placeholder 模式    → 模板框架 + AI 段落 token + 批量差异化 QC
```

**三种模式共同要求**：
- **禁止占位文本**（Lorem ipsum / "Coming Soon"）
- **禁止图片复用**（关键视觉位每张独立 prompt）
- **依据可追溯**（基于上游证据 + 业务事实，不凭通用知识编造）
- **先依据后构建**（每个页面/主题线先完成依据包再写内容）
- **动态区数据源在构建时决定**（产品区/博客区等动态模块在构建阶段选定 shortcode/WP Query/REST，不用静态假卡片占位）

**模式级差异**：

| 模式 | 单页 Brief | 实例页差异记录 | QC 层级 |
|------|-----------|--------------|---------|
| 精做 | 必填（完整字段） | 必填 | 单页 QC |
| config-driven | 模板级（字段表） | 字段值差异（不写完整 Brief） | 批量差异化 QC |
| placeholder | 模板框架 | token 填充差异 | 批量合规 + Schema 校验 |

#### 2D 上传与前端验收

**核心规则**：
- **单页试点先行**：第一个页面必须走完全闭环（生成→图片→上传→前端验收），验证通过再批量推进
- 逐页闭环，不做完当前页面不开始下一个
- **前端验收必须打开 preview URL 确认**，不能只看 API 返回 200
- **动态内容必须接真实数据源**（不用虚拟产品卡/虚拟文章卡/Lorem ipsum 冒充）

**验收清单**（每页上传后必过）：HTTP 200 + canonical / Title+Meta+H1 含目标关键词 / 导航可达 / 移动端首屏无横向滚动 / 动态区接真实数据 / 图片 webp+alt 完整 / 内链 3-5 条 / JSON-LD Schema 通过。

> 详细操作见 §5 调用规则。

### 步骤 3：内容策略与内容营销

**定位**：本节是**控制面**（目标、门槛、路由、产出物归属）。具体批量生产 SOP 见 `07-英文SEO批量写作与去AI化工作流.md`。

**跨步骤依赖**：内容清单草案可先启动；最终 URL、承接页面、内链规则、内容 Brief 需等步骤 2（2A+2B）完成后锁定或复核。

#### 3.1 内容清单与批次

**核心原则：一次性做草案，分批进入正式 Brief**。

- 内容清单分两层：**执行清单**（首批完整字段）+ **候选池**（轻量字段，等批次轮到再补）
- 草案可一次性生成，正式 Brief 必须在数据补齐后锁定（KD/CPC、竞品验证、URL、内链规则）
- 用"发布节奏"代替"优先级"，每篇标注建议发布顺序

**批次规划原则**：

| 原则 | 说明 |
|------|------|
| 先核心后扩展 | 首批覆盖核心 Topic Pillar 高价值关键词 |
| 按意图分层 | 每批包含不同意图类型，验证意图→内容匹配 |
| 批次大小 | 每批 10-30 篇 |
| 验证门槛 | 首批发布后观察 2-4 周，有收录排名信号再启动下一批 |
| 主题集中 | 单批不跨太多 Pillar |

**内容清单字段**：目标关键词 / Volume / KD / CPC / 搜索意图 / 内容类型 / 对应 URL / 竞品验证状态 / 建议发布节奏 / Brief 状态。详细模板见 `03-模板库/05-内容清单字段模板.md`。

#### 3.2 Brief 锁定门槛

**Brief 锁定是内容从"规划"进入"生产"的 gate**。

**锁定门槛**（全部满足才能锁定）：

| 门槛项 | 要求 |
|--------|------|
| 关键词与意图校验 | Brief 声明目标关键词、搜索意图、数据来源、结构依据。模板化实体页可"框架级关键词校准 + 单篇轻量检查"；非模板化长文需补单篇关键词证据 |
| 关键词数据完整 | 目标关键词已有 Volume/KD/CPC/意图标注 |
| 竞品验证完成 | 至少 2-3 篇竞品内容已复核（覆盖结构和关键论点） |
| URL 和承接页面确定 | 步骤 2B 已决策 |
| 内链规则明确 | 与已有内容的内链关系已规划 |
| 选题角度差异化 | DREAM 检查至少一项结构/视角/信息增量差异 |

**DREAM 模型 — Brief 角度检查**：

| 维度 | Brief 中对应的检查 | 未覆盖时的风险 |
|------|------------------|-------------|
| **D** — Demand（需求） | H2 是否说明了"为什么需要" | 用户看不到相关性 |
| **R** — Reason（理由） | 是否给出"为什么选这个" | 用户无法做比较 |
| **E** — Evidence（证据） | 是否有数据/案例/来源支撑 | 信任不足，AI 不引用 |
| **A** — Advantages（优势） | 是否展示了具体差异化 | 淹没在同质内容中 |
| **M** — Motivation（动机） | 是否给了"现在行动"的理由 | 流量不转化 |

> DREAM 可直接嵌入 Brief 大纲：H2 需求场景（D）→ H3 理由（R）→ H3 证据（E）→ H2 优势（A）→ H2 行动动机（M）。详细见 `08-AI内容增长引擎-ACE模型.md`。

**品牌语调配置**：首次 Brief 锁定前完成定义（存放在项目 `03-内容策略/品牌语调配置.md`），Brief 模板引用配置不重复定义。

#### 3.3 发布前质检路由

**质检路由矩阵**：

| 检测项 \ 内容类型 | 百科/科普 | 对比/选购 | 教程/How-to | 转化型 | 工具 |
|-----------------|----------|----------|------------|--------|------|
| EEAT 质量评估 | ✅ 标准 | ✅ 加强 | ✅ 标准 | ✅ 轻量 | — |
| 站外原创性 | ⬜ 可选 | ✅ 必做 | ⬜ 可选 | ⬜ 跳过 | — |
| 站内重复 | ✅ 必做 | ✅ 必做 | ✅ 必做 | ✅ 必做¹ | — |
| GEO/AI Citation | ✅ 必做 | ⬜ 可选 | ⬜ 可选 | ⬜ 跳过 | — |
| Schema 类型 | ⬜ 可选 | ⬜ 可选 | ⬜ 可选 | ✅ 必做 | ✅ 必做 |

**通过标准**：DREAM 5 维至少覆盖 3 项 + 该内容类型"必做"项全通过 + 无 AI 化高风险段落 + 内链指向页面已存在。

**条件覆盖**：
- 若内容优先目标含"AI Citation"，所有站内内容至少做轻量 GEO 检查
- ¹ 模板化产品页、集合页、pSEO 批量页面**必做**站内重复检测

#### 3.4 发布与内链承接

**发布前检查**：URL 规则一致 / Meta 三件套完整 / 内链双向确认 / 图片已上传 / 分类标签正确。

**内链规则**：上下层级（产品百科 → 分类 → 产品）/ 主题关联（同 Pillar 互相链接）/ 意图递进（信息 → 商业 → 交易）/ 描述性锚文本（不用"点击这里"）。

### 步骤 4：社媒内容分发（可选）

将步骤 3 创作的博客文章再加工为多平台社媒内容，最大化内容 ROI。内容稳定后再启动。详细流程见 `04-社媒内容分发工作流.md`。

### 步骤 5：商业模式（可选）

适用于 SaaS、内容站、Affiliate 等需要设计变现路径的项目。B2B 外贸站通常可跳过。
