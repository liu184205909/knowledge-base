# 批量排程架构方案：一次排几百条 + 错峰 + 免日常关注（cushionmill.com）

> 调研日期：2026-10-07 | 前置文档：`pinterest-tools-调研.md`（工具生态/ToS/API 细节）、`facebook-automation-调研.md`（FB 路线/CDP 红线）
> 本文聚焦一个问题的最终架构：**如何把几百条素材排成定时队列，之后零日常维护**。来源分级：官方明文 > 厂商文档 > 行业分析 > 社区。

---

## TL;DR

**推荐架构 = Pinterest 线 agent 本地队列（Trial token 现在就能跑，不必等 Standard）：素材库 JSON 一次性灌 ~500 条 pin → Windows 计划任务每小时唤醒 dispatcher → 按美东流量峰时刻表每日发 3-4 条 → 发布状态写回 JSON。FB 线 = Buffer Essentials 1 频道 $6/月，CSV 100 条/次批量上传，队列上限 5000 条，同样零日常维护。**

现有资产可支撑 **首批 ~500 条 pin（含模板变体可扩至 ~800 条）**，按 3.3 条/天节奏 = 首批吃 5 个月，变体池吃 8 个月。

## 一、三通道容量对比（2026-10 核实）

| **Tailwind 付费档** | Pro 150 帖/月 $29.99 · Advanced 300 帖/月 ~$47.99 · **Max 无限 $99.99**（年付约半价） | 无限 | 批量上传 + SmartSchedule | $17.99~99.99/月 | 付费；几百条队列要 Max 档 |
| **Buffer 付费档** | **5,000 条/频道**（官方 "unlimited" 的实际 cap） | 无限 | **CSV 100 条/次上传**（付费档） | $6/频道/月（年付 $5） | 付费；Pinterest+FB 两频道 $12/月 |

关键不对称优势：**Pinterest 原生/第三方通道的"定时窗口"都是 30 天或厂商档位，唯独自建队列没有窗口**——这正是"一次排几百条、免日常关注"的核心诉求，只有 agent 队列真正满足（Buffer 5000 条 cap 也满足，但要月费且数据回流弱）。

| CDP 批量录入 MBS | 同 MBS | 29 天 | 半自动 | $0 | **红线区**：Meta 主动检测自动化，有封整个 BM 实锤（详见 `facebook-automation-调研.md` §五），不推荐 |

## 二、发布时间科学（2026 数据口径，美东）

### Pinterest（home décor / 电商类目）

| 时段（ET） | 强度 | 依据 |
|---|---|---|
| **周六早 ~8:00** | 单点最强窗口之一 | Postlia 2026（"evening-and-weekend planning platform"） |
| **工作日晚 20:00-22:00** | 最强常驻窗口 | Viraly 2026 / Hopper HQ 共识 |
| **午间 12:00-13:00** | 次强（午休峰） | 多源一致 |
| **周末下午 14:00-16:00** | 次强 | OnlySocial 等 |
| 周五-周日 | 家装"refresh"内容的加权日 | Pinterest moments marketing 口径 |

home décor 是 Pinterest 核心"规划型"类目，用户在晚间/周末的浏览-收藏会话中决策，且**季节性内容提前 30-60 天布局**——与我们节令线"目标下一季"纪律同构（指针：`seo-line-longterm-not-seasonal`）。

### Facebook（Page，美国受众）

- 峰：工作日 9-11AM / 12PM / 5-7PM ET；**周二-四最强，周末最弱**（与 Pinterest 相反！）
- 频率共识：**1 帖/天最优**，最多 2；FB organic reach ~4.5%，FB 线定位=门面+广告前置资产（详见 `facebook-automation-调研.md` §六），不值得高投入

### 每日条数（Pinterest）

| 账号阶段 | 每日 fresh pins | 来源 |
|---|---|---|
| 新账号（我方现况） | **3-5**（甜点区） | Tailwind 2025 |
| 成熟账号 | 1-10 | 多源共识 |
| spam 风险区 | 50+（避免） | 多源共识 |

旧口径"15-25/天"已过时且反效果——算法奖励 **fresh 图**（新图/新设计），不是量。注意 fresh 判定看**图**：同图配不同文案 ≠ fresh pin；扩量必须靠模板合成新图（§三）。

## 三、推荐架构（Pinterest 主线）

### 3.1 素材库规模：现有资产 → pin 总量

| 资产 | pin 化方式 | 条数 |
|---|---|---|
| 160+ product 页图库 | 每页 2 pin（主图 pin + 场景/细节图 pin，链到产品页） | ~320 |
| 40+ 文章图 | 每篇 3-4 pin（教程/选型意图是 Pinterest 流量主力，链回文） | ~130 |
| 测量指南 | 常青 pin 2-3 条 | ~3 |
| **首批合计** | | **~450-500 条** |
| 二批模板变体 | 每产品页挑 1 图做"品牌色顶栏+标题文字"合成版（Pillow/HTML→PNG，同 postonce pin-maker 思路）= 新图 = fresh pin | +160 |
| **含变体池** | | **~650-700 条** |

按周 23 条（3.3/天）节奏：首批 ~5 个月，含变体 ~8 个月。期间新文章/新品页持续产新 pin 入池——**一次建池，长期收租**（pin 半衰期月级，指针：`pinterest-tools-调研.md` §3）。

### 3.2 队列设计（pin_queue.json）

```json
{
  "id": "P-0342",
  "image_url": "https://cushionmill.com/wp-content/uploads/.../deep-seat-cushion-navy-1000x1500.png",
  "title": "Deep Seat Cushion Replacement for Outdoor Sofa",
  "description": "Custom replacement cushions...",
  "board": "outdoor-cushion-replacement",
  "link": "https://cushionmill.com/product/deep-seat-navy/?utm_source=pinterest&utm_medium=social",
  "scheduled_date": "2026-11-14",
  "slot": "evening_peak",
  "status": "pending",   // pending | published | failed | skipped
  "pin_id": null,
  "published_at": null
}
```

- **status 状态机**是免维护的关键：发布成功写回 `pin_id`，dispatcher 重复触发时跳过已发布槽位（幂等）
- 一批生成时按"内容类型轮转"排日期：产品 pin / 文章 pin 交错（避免同日 4 条全是产品图，账号画像单一）

### 3.3 cron 节奏与错峰时刻表（美东）

**dispatcher 触发**：Windows 计划任务每小时唤醒 `pin_dispatcher.py` → 脚本用 `zoneinfo` 计算当前 **America/New_York** 时刻 → 命中当日槽位窗口（±10 分钟）且该槽未发 → 调 API 发 1 条。
- 时区感知调度使 DST 切换（11 月初 EST）自动正确，免维护
- 脚本逻辑 ~100 行 requests（token 刷新 + media 上传 + create_pin + 状态写回），与 `pinterest-tools-调研.md` §6 阶段 2 同构

**每日槽位表**（分钟数刻意非整点，避开机器突发特征）：

| 槽 | 时刻（ET） | 对准的峰 | 周一-五 | 周六/日 |
|---|---|---|---|---|
| noon | 12:30 | 午休峰 | ● | ● |
| evening | 20:30 | 晚峰主力 | ● | ● |
| evening2 | 21:10 | 晚峰次槽 | ● | — |
| weekend_am | 8:05（六）/ 8:35（日） | 周末早峰（home décor 最强单点） | — | ● |

= 周一~五 3 条/天，周末 4 条/天，**周 23 条**，落在新号 3-5/天甜点区。

### 3.4 rate limit 预算（结论：毫无压力）

| 限额口径 | 值 | 我方占用 |
|---|---|---|
| pin 创建（保守口径，clugtu/pinterest-mcp） | 10 pins/min + 250 pins/天 | 每小时 dispatcher 至多发 1 条 → **1.6%/天** |
| Trial app 级 | ~1,000 calls/天 | 每条 pin = 2 calls（media+pin）→ 8 calls/天 |
| Standard（审批中） | 100 writes/min 级 | 同上，更宽 |

即：**当前 Trial 权限已实测可发 production pin（2026-10 验证），架构无需等 Standard**。Standard 批准只是解锁更高速率上限（对 3.3 条/天无意义）+ 合规余量。审批被拒的重提预案见 `pinterest-tools-调研.md` §6。

## 四、FB 线方案

**推荐：Buffer Essentials 1 个 FB 频道（$6/月，年付 $5）**

1. CSV 一次上传 100 条（付费档），队列 cap 5,000 条 → 一次灌 3 个月（1 帖/天 × 90 天）绰绰有余，**真正免日常关注**
2. 频率：1 帖/天（共识最优）；时刻定 **周二-四 12:05 ET** 加权（FB 午间峰+强日）——Buffer 支持自定义 posting schedule
3. 素材复用 pin 池的图 + 另一套 FB 文案（FB 帖文案口语化，pin 描述 SEO 化，同一批图两用）
4. 成本年付 $60，买断"FB 线永久免维护"；比 CDP 录入安全（零封号风险），比 MBS 手动省 12 次/年的月度排程会

**替代（不想付费）**：MBS Planner 人工月度会——每 29 天坐一次，排 29-30 条（1 帖/天），约 60-90 分钟/月。29 天窗口是平台硬限制，无法突破，这是 FB 原生通道的结构性天花板。

**CDP 半自动录入 MBS**：维持红线结论不推荐（Meta 主动检测自动化+连坐封 BM 实锤，`facebook-automation-调研.md` §五）。若未来确需，只允许人在场监督+≥30s/条拟人间隔，且不可过百条/次。

### 等待期（Standard 审批中，非阻塞）

- Standard 批准 → 仅影响速率上限（当前占用 1.6%，无实际收益变化）；架构零改动
- Standard 被拒 → 按两大被拒原因补拍 OAuth demo 重提（`pinterest-tools-调研.md` §6 阶段 1）；期间 **CSV Bulk Create 是 API 的降级备用通道**（200 条/文件批量+定时，免费原生）
- Token 过期处理：refresh token 自动续期写进 dispatcher（失败即告警，禁静默重试轰炸）

## 六、纪律（从本文架构派生）

1. **fresh 铁律**：扩量只靠新图（模板合成变体），禁同图多文案重发——后者不算 fresh 且是 spam 画像
2. **错峰分钟抖动**：所有定时落非整点（:05/:30/:10/:35），多账号未来扩展时槽位再错开 ≥40 分钟
3. **队列先审后发**：批量生成的 pin 上线前过一遍 agent 自查（标题/描述关键词、链接可达、图 1000×1500）——Developer Guidelines 明文禁止"用户未逐条考虑的自动动作"，审查关口是合规要件（指针：`pinterest-tools-调研.md` §1.4）
4. **两通道不混帖**：API 发的帖归 API 管（FB 侧 "app 自帖自管" 明文）；FB 若走 Buffer，某帖就全程归 Buffer
5. **数据回流每周一次即可**：outbound_clicks 是唯一信任指标（impression 可注水），周报汇总砍弱留强，不做实时监控
